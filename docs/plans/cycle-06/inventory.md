# サイクル 06 の台帳の棚卸し

サイクル 06（M42・M43・M44・M45・M46・M41 の残り）の終わりに、残件と改善の候補の 2 つの台帳を全部読み直した記録である。手順は `guides/cycle-end.md`「5. 台帳の棚卸し」にある。作者への一覧は、サイクル末の PR の本文の冒頭に貼る。答えが要る問いの説明は、1 件ずつ `author-decisions.md` に書いた（`guides/dev-cycle.md`「1. 計画レビュー」）。

## 作者への一覧

作者の判断が要る `blocked-user` と、作者が不在の間に取りまとめ役が決めた `judgment` である。内容と判断の理由は `plans/open-items.md` の各行にある。作者が最初に読む問いを先に置き、残りを ID の順に並べる。

### 先に決めてほしい問い

サイクル 07 の計画レビューの前に答えがほしい。どれも答えで作るものが変わるので、答えが来るまでその部分に着手しない。説明は `author-decisions.md` の 1〜3 にある。

1. **取り消した伝票の合計金額の欄（OI-192）**。照合待ちのまま取り消した受注に「照合待ち」と出る。いまのまま、「—」、「取消」から選ぶ
2. **取引先の名前と品目の名前の並び順（OI-190）**。いまは DB の照合順序で、漢字を含む名前の並びが流用元と変わる。いまのまま、ICU の日本語の照合順序で流用元と同じ並びにする、読みの列を持つ、から選ぶ
3. **一覧の見出しで複数の列を指定する操作（OI-187）**。いまの計画はかんばんの並びだけで使う。見出しで 2 つ目からの列を足す操作を作るかを選ぶ

作者が手を動かすことは、公開の配置の実機の手順（M41 の残り、`deploy/README.md`「作者の手順」1〜6）と、M33 の画面の細かい指摘（OI-177）である。

## 残件の読み直し

`open` の行を全部読んだ。要らなくなった行は無かった。

| ID | 引当先 | 読み直した結果 |
|---|---|---|
| OI-177 | M33 | 作者の画面の細かい指摘。作者が出すまで残す。M33 の「残り（サイクル 07）」の表にある |

足した行は、OI-192（逸脱検査の作者の判断）である。M33 の「残り（サイクル 07）」の表に OI-192 の行を足し、取消依頼のボタンの直しに、E2E の前の期待を直すこと（逸脱検査 D3）を書いた。OI-182 の内容に、`pg_isready` に `-t 4` を渡したことと理由（M41 の残りの実装レビューの Claude R2）を書き足した。判断の根拠の一部だからである。閉じた行は無い。

`bin/check-open-items --due` を、サイクル 06 のマイルストーンのそれぞれで流した。M42・M43・M44・M45・M46 は通った。M41 も通るが、作者の実機の手順が台帳の外（計画の M41 の「残り」の表と `deploy/README.md`）で残るので閉じない。実機の手順だけをサイクル 07 へ移し、計画の M41 に「残り（サイクル 07）」を書いた（`guides/dev-cycle.md`「全体の流れ」）。M33 は OI-177・OI-192 で落ち、サイクル 07 のマイルストーンのままである。

計画の M44 の作者の手順の「`@types/node` 26 の PR を閉じる」は、M44 をマージした後に Dependabot が自分で閉じたので要らなくなった。開いたまま残る Dependabot の PR は、`typescript` 7 の #66・`eslint` 10 の #70（どちらも計画どおり開いたまま。IB-99・IB-103）と、`groups` による最初のまとめた PR #77（`lucide-react` 1.55.0、CI はすべて通った）である。#77 のマージは作者に任せる。
