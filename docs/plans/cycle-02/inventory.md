# サイクル 02 の台帳の棚卸し

サイクル 02（M34・M35・M21〜M24）の終わりに、残件と改善の候補の 2 つの台帳を全部読み直した記録である。手順は `guides/cycle-end.md`「5. 台帳の棚卸し」にある。作者への一覧は、サイクル末の PR の本文の冒頭に貼る。

## 作者への一覧

### 先に決めてほしい問い

1. **業務の mutation に役割の制限を置くか（OI-71・OI-72・OI-73）**。M22〜M24 で足した `cancelSalesOrder`・`inspectInboundShipment`・`setBillingTerm`・`closeBillingPeriod`・`discardDraftInvoice` は、どれも「自社のユーザーなら役割（`admin`・`member`）を問わない」にした。`graphql-schema.md`「役割による制限」は、取引関係の変更（`admin` だけ）のほかに役割の制限を置かず、実装者はその規則と、前のマイルストーンの規則（審査の承認 `review?`・取消依頼 `request_cancellation?`）に合わせて同じ判断を 3 回積んだ。請求の締めと破棄、受注の取消を `admin` に限るなら、3 つの policy と行列テストの行を変える
2. **SDL にあって実装に無い一覧の `filter` をどうするか（OI-78）**。`graphql-schema.md` の SDL は `purchaseOrders`・`salesOrders`・`stocks`・`shipmentRequests`・`invoices` に `filter` を持つが、どれも実装していない（OI-76 で `InvoiceFilter` も作らなかった）。画面（M33）で項目が決まるまで SDL から外すか、目標の形として残すかを決める（逸脱検査 D1）

## 残件の読み直し

`open` の 3 行を全部読んだ。要らなくなった行は無かった。OI-77 は、逸脱検査で業務の振る舞いを変える判断と裁定したので `blocked-user` にした。

| ID | 引当先 | 読み直した結果 |
|---|---|---|
| OI-15 | M28 | 通知（M28）の前に SendGrid の文書で確かめる作業で、まだ要る |

| OI-77 | M25 | 未来の締め日を確定と一緒に決める。逸脱検査で M25 の節の作るものに無いと分かったので、M25 の節に足し、作者の判断に回した（`conformance.md` D3） |

`bin/check-open-items --due` を、終えたマイルストーン（M15〜M20・M34・M35・M21〜M24）のそれぞれで流し、すべて通った。引当先のマイルストーンを終えたのに残っている `open` と `blocked-user` は無い。`judgment` の 53 行は、引当先が終えたマイルストーンを指したままである。`judgment` は作者の確認を待つ行で、`--due` は止めず、作者は上の一覧で確かめる。

閉じた行は無い。足した行は OI-78（逸脱検査 D1）と OI-79（IB-22 を残件に移した。下の節）で、OI-79 は M26 の作るものに足した。
