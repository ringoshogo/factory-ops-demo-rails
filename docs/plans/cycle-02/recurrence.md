# サイクル 02 の再発防止

サイクル 02（M34・M35・M21〜M24）で直し終えた指摘と食い違いの原因をたどり、同じ種類が再び起きない仕組みを足した記録である。手順は `guides/cycle-end.md`「4. 再発防止」にある。直すこと（是正）は各マイルストーンと逸脱検査で済んでいるので、ここでは予防だけを扱う。知見の収穫（`harvest.md`）に書いた知見は、ここに書かない。

読んだものは、実装レビューの指摘（Critical・High は無く、Medium と、振り返りで 2 回以上と数えた種類の Low）、逸脱検査の食い違い（`conformance.md`。「文書が正」の裁定は無く、「実装が正」の D2 は直す前の形を数えなかった直しの残りなので、ここで扱う）、振り返りの想定外と回し方の改善の提案である。指摘は、振り返りの「指摘の数」の種類ごとにまとめ、まとめた行に出どころをすべて挙げた。

## 指摘ごとの種類・原因・修正先

種類は、範囲の逸脱 → 生成物のずれ → 規則の違反 → 文書との食い違い → 暗黙の知識、の順に当てて最初に当たったものにした。「捕まえるべきだった段階」は、計画レビュー・実装・実装レビューのどれかである。

| 指摘（出どころ） | 種類 | なぜ起きたか | なぜ防げなかったか | 捕まえるべきだった段階 | 修正先と分類 | 再び起きたら捕まる段階 |
|---|---|---|---|---|---|---|
| 実装が無くても通るテスト：空どうしの比較・最後の状態だけ・期待値を実装から作る（M21 X1・X2・X3、M23 C3、M24 X2・C2・C3） | 規則の違反 | 否定（届かない・ならない・空になる）を確かめる example で、肯定の側が成り立つ準備を置かなかった。S1 の一覧の行は、発注側が自社の行を持たないので、絞り込みを外しても空のままだった | 実装レビューの観点 4 が名指しするが、実装の時点で止める仕組みが無かった。取りまとめ役が依頼に「最初から満たす」と書いても、M23・M24 でまた出た | 実装 | S1 の一覧を絞る行で、絞らない一覧が空でないことを spec が先に確かめる（仕組み）。単体の否定の example は、同じ準備で肯定の側を先に確かめる（対照）ことを `dev-cycle.md`「テストから書く」に書いた（手順） | CI（S1）。単体は実装レビュー（観点 4） |

## 機械にした検査と、壊して落ちることの確かめ

どの検査も、先に spec を書いて落ちることを見てから、実装か準備を足した。壊したファイルは複製から戻し、戻した後に更新時刻を進めた。

| 検査 | RED と壊し方 | 落ちたもの |
|---|---|---|
| `spec/platform/compile_cache_spec.rb` | `config/boot.rb` を変える前に流した | `同じ秒に同じ大きさで書き換えたファイルを、書き換えた後の中身で読む`（`got: "1"`）。設定を足した後は通る |
| `spec/graphql/audit_examples_spec.rb` | `spec/requests/cancellations_spec.rb` を M21 の指摘の前の版（`6076687`）に戻す | `cancellation_review.approve`・`cancellation_review.reject`・`purchase_order.request_cancellation`・`sales_order.cancel` の 4 件（M21 C1 と、その時点で無かった M22 の 1 件） |
| `spec/db/lock_sites_spec.rb` | 出荷の競合テストを M21 の指摘の前の版（`6076687`）に戻し、審査の競合テストを消す | `Fulfillment::SalesEventReceiver.hold`・`Sales::CancellationReviews.decide` の 2 件（M21 C2 の 3 か所のうち 2 か所。取消依頼の受け手のロックは、M22 で足した受注側の取消の競合テストがいまは確かめる） |
| 同上 | 請求の公開 API にロックを取るメソッドを 1 つ足す | `ロックを取るメソッドは、すべて表にあり、表のメソッドはすべてロックを取る` |
| `spec/scenarios/tenant_boundary_spec.rb` の対照 | 対照を足した直後、準備を足す前に流した | `SupplierView.stockMovements(itemId)`・`SupplierView.partMappings(customerTenantId)` の 2 件。どちらも発注側が自社の行を持たず、空どうしの比較だった。M24 C3 と同じ種類が、指摘の無かった 2 行に残っていた |
| 同上 | 在庫の移動履歴の公開 API から品目の絞り込みを外す | 新しい S1 では `SupplierView.stockMovements(itemId)` が落ちる。対照を足す前の S1（`74b4ceb`）では、同じ壊し方で 29 examples がすべて通る |

`spec/db/lock_sites_spec.rb` の表は、ロックを取る 33 のメソッドのうち 23 を競合テストに、10 を理由に結んだ。理由の行は、取りまとめ役が書いたもので、実装レビューと次の改善の探索で、競合テストを足すべきかを見る対象である。メソッドの名前とファイルの文字列で照らすので、競合テストがそのロックの組み合わせ（たとえば同じ下書きの 2 つの破棄）を確かめるかまでは見ない。M24 X1 は、破棄と締めの競合テストがすでにあったので、この検査では捕まらない。
