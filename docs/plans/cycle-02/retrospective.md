## 回し方の改善の提案

`guides/dev-cycle.md` か本書への変更として書く。機械で止められるものは、再発防止（段階 4）で検査を足すので、ここでは提案だけを書く。

1. **複数のマイルストーンを渡すレビューでは、マイルストーンごとに判定を出させる**（`dev-cycle.md`「依頼の型」の出す形）
2. **レビューの対象の版を commit で固定する**（`dev-cycle.md`「依頼の型」の対象）。依頼に対象の commit の SHA を書き、レビュアーは作業ツリーではなくその commit のファイルを読む。取りまとめ役は、レビューの間に同じ作業ツリーを書き換えない
3. **レビュアーの結果は最終報告で取りまとめ役に返させる**（`dev-cycle.md`「独立したレビュアー」）。レビュアーから実装者へ直接送らせない。取りまとめ役が受け取り、証跡に写してから実装者に渡す
4. **長い依頼を分ける**（`dev-cycle.md`「1. 計画レビュー」）。レビュアーが止まったら、同じ依頼で出し直し、出し直したことを証跡に書く
5. **3 つの繰り返す種類を機械で止める**（再発防止）：監査の行の中身を確かめる example、ロックの直列化を確かめる競合テスト、相手のデータに届かないことを対照なしで確かめる S1 の行
6. **壊して確かめるときに古い版を読まない**（再発防止）：テストの環境で bootsnap の命令列のキャッシュを使わない
7. **理由が後から分からなくなる変更に、理由のコメントを残す**（`guides/comments.md`「書くこと」、作者の要望）
