# サイクル 10 の振り返り

サイクル 10（M57・M54 の残り・M33 の残り・M41 の残り）の計画が実装にどれだけ合っていたかと、回し方そのものが働いたかを評価した記録である。手順は `guides/cycle-end.md`「1. 振り返り」にある。ここで挙げた想定外は、知見の収穫（`harvest.md`）と再発防止（`recurrence.md`）の入力になる。

読んだものは、計画レビューの証跡（`plan-review.md`）、実装レビューの証跡（`implementation-reviews.md`）、サイクルの commit の履歴（`aba5836..7b03877`）、計画の節を直した commit、台帳 2 本、`handoff.md` である。取りまとめ役が担当とレビュアーを動かしたときに見たことは、リポジトリに残らず、この振り返りの入力にも無いので、ここには書いていない。

## 回し方の改善の提案

`guides/dev-cycle.md` か `guides/cycle-end.md` への変更として書く。機械で止められるものは、再発防止（段階 4）で検査や設定を直すので、ここでは提案だけを書く。

1. **完了条件の `git grep` を最後の版で流した件数を、`bin/check-open-items` が証跡で確かめる**。計画の節の完了条件にある `git grep` のコマンドが、そのマイルストーンの実装レビューの節に件数とともにあることを、次のサイクルからの証跡で落とす。PR の CI の実行の URL は、同じ commit の中に自分の CI の結果を書けないので、検査にしない。想定外 3 の予防である
2. **実装レビューの観点 1「計画への準拠と範囲」に、「計画との違い」の「判断なし」の項目ごとに、計画の文のとおりか前提が実物と合っただけかを見ることを足す**（`dev-cycle.md`「実装レビュー」）。規則に照らして決めたことと、前提が崩れて決めたことも、作者が確かめていなければ `judgment` にすると「作者が不在の間に決めたこと」に書く。想定外 4 の予防である
3. **`judgment` の行の一部だけを作者が確かめたときは、行を `judgment` のまま、内容の欄の末尾に「作者の確認（日付）：…」と確かめた範囲を書く**（`dev-cycle.md`「残件の台帳」）。想定外 5 の予防である
4. **改善の探索の起動の表に、「`起票済み` の行を起こしたマイルストーンを終えた」を足し、その行の効き目を確かめるために回す**（`cycle-end.md`「5. 台帳の棚卸し」）。想定外 7 の予防である
5. 計画の壊して落ちる記録の表の予想の外れ（想定外 6）と、計画の手で数えた分け方の誤り（想定外 2）は、計画レビューか実装で捕まり、手順のとおりに直った。足すものは無い
