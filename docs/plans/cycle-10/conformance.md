サイクル 10（M57・M54 の残り）の成果物が正本から外れていないかを、2 系統のレビュアーが検査した記録である。手順は `guides/cycle-end.md`「3. 逸脱検査」にある。ここで「文書が正」と裁定した食い違いは、再発防止（`recurrence.md`）の入力になる。

レビュアーに渡したのは、サイクルの diff（`aba5836..46eb22e`。`46eb22e` は知見の収穫の commit）、サイクル末のブランチの diff（`7b03877..46eb22e`）、正本（知見の収穫で足したものを含む）、サイクルのマイルストーンの節（M57 と M54 の「残り（サイクル 10）」）、振り返りの「計画から実装への逆向きの照合」、実装レビューの証跡、台帳である。依頼には読む版を `46eb22e` と書き、その版を展開したディレクトリだけを読ませ、このサイクルに固有の確かめどころ（出荷指示の取消のロックの順とコードの一致、`ignored_columns` の規則と 2 つのモデル・マイグレーション・移行の spec の一致、公開 API の定数の別名と enum の比べる組の分け方、ADR 011 の直しと OI-229 の裏返る条件、M54 の残りで直したコメント、「判断なし」と書いた 8 項目と振り返りの見立て、計画の節の直し）を観点の下に足した（`guides/dev-cycle.md`「依頼の型」）。どちらもテストは流さず、ファイルと行を照らした。Claude のサブエージェントは最終報告を返さずに終わり、依頼に書かせたファイルから結果を読んだ。Codex は `--skip-git-repo-check` を付けて読み取りだけで流し、一時の失敗を起こさなかった。

## 違和感

- **`showcase.md` テーマ 4 に足した文は、デッドロックしない理由を「計上の順の部分列」だけで言い、設計文書のもう 1 つの理由（受注の取消とは同じ行を取らない）を省く**（2 系統）→ 知見の収穫で足した文なので、両方の理由を書く形に直した
- **`Inventory::Stocks::MOVEMENT_EFFECTS` は凍結した Hash を出すが、値の配列は凍結していないので、別のパッケージが増減の向きを書き換えられる**（Claude）→ 改善の候補 IB-155 に積んだ
- **`Imports::Import::KINDS` は本番のコードのどこからも読まれない**（Claude）→ 改善の候補 IB-156 に積んだ
- **知見の収穫の「書かなかった項目」と OI-226 の結果の欄は、`list-pagination.spec.ts` のコメントを「ADR 011 を指す文にした」と書くが、実物のコメントは ADR 011 を指していない**（Claude）→ 知見の収穫の行を、いまの契約の短い文にした、に直した。OI-226 の結果の欄は閉じた時点の記録なので書き換えない。計画が求めたのはいまの契約の短い文で、コメントは規約に合う
- `config.md` の規則 3 は、移行の spec に足した順によらず落ちる example に触れない（Claude）→ 誤りではなく、見せどころのテーマ 10 が触れるので、変えない
- `ignored_columns` の規則 2 は、作者が確かめた割り切りと、確かめていない細部（OI-232）の区別を台帳が保っている（Codex）→ そのまま。作者への一覧で残りを問う
- IB-154 は規則 3 を否定せず、別の候補として扱う今のままでよい（Codex）→ そのまま

## 再発防止へ渡すもの

「文書が正」の裁定のうち、再発防止で扱うのは D1・D2・D3・D5・D6 である。D1・D2・D5 は、「判断なし」と書いた項目に決めたことが混ざったもので、振り返りの想定外 4 と同じ種類である。D6 は、計画の作るものと違う形にしたのに計画の節を直さなかったもの、D3 は、規則を変えたときに前の根拠を指すコメントが言い回しの違う形で残ったもので、どちらも同じマイルストーンの実装レビューが挙げなかった。
