# サイクル 07 の振り返り

サイクル 07（M48・M49・M47・M50・M33 の残り・M41 の残り）の計画が実装にどれだけ合っていたかと、回し方そのものが働いたかを評価した記録である。手順は `guides/cycle-end.md`「1. 振り返り」にある。ここで挙げた想定外は、知見の収穫（`harvest.md`）と再発防止（`recurrence.md`）の入力になる。

読んだものは、計画レビューの証跡（`plan-review.md`）、実装レビューの証跡（`implementation-reviews.md`）、サイクルの commit の履歴（`2e10f5b..cd585d3`）、計画の節を直した commit、台帳 2 本、PR #83〜#89 の状態、M48 をマージした後の main への push の CI の記録である。取りまとめ役が担当とレビュアーを動かしたときに見たこと（担当への判断の受け口、担当の push、手元のマシンの負荷、一時の DB）は、リポジトリに残らないので、取りまとめ役の観察としてここに書いた。

## サイクルの終わり方

サイクル 07 は、計画レビューの時点の 6 つのまま終えた。途中で増えたマイルストーンは無い。

M33 の残りは、OI-178（取消依頼のボタン）と OI-192（取消済の伝票の合計の表示）を実装レビューまで終えた。作者の画面の指摘（OI-177、`open`）は来ていないので、計画の「残り」の規則（`implementation-plan.md` M33「残り（サイクル 07）」）のとおり、OI-177 だけを「M33 の残り」としてサイクル 08 へ移した（`inventory.md`）。`bin/check-open-items --due M33` は OI-177 の 1 行だけで落ちる。

## 回し方の改善の提案

`guides/dev-cycle.md` か `guides/cycle-end.md` への変更として書く。機械で止められるものは、再発防止（段階 4）で検査や設定を直すので、ここでは提案だけを書く。

1. **担当への依頼に、`git push` にも `GH_TOKEN` を付けることを書く**（`dev-cycle.md`「ブランチと PR」、`handoff.md`「開発環境」）。想定外 3 の予防である。手順の文書が「push・PR」と書いていても、依頼の型が gh だけを挙げると、担当は `git push` を素で流す
2. **取りまとめ役が担当の受け口に判断を書くときは、台帳の行を読んでから、行の状態をそのまま写す**（`dev-cycle.md`「残件の台帳」）。想定外 2 の予防である
3. **手元で E2E の全体が通らないときに、同じ commit の PR の CI の `e2e` の実行を証跡に書いてからレビューに出す**（`implementation-plan.md`「1 つのマイルストーンの進め方」4）。M50 と M33 の残りの「証跡の欠け」3 件の予防である。手元の遅さそのものは改善の探索で扱う
4. **積み重ねた PR の最上段の担当は、`handoff.md` の実装の行に、まだ書かれていない下の段のマイルストーンも書く**（`dev-cycle.md`「ブランチと PR」）。想定外 11 の予防である
5. **一時の DB の後片付けを担当の終わりの手順に置くか**は、改善の探索に送った（想定外 4）
