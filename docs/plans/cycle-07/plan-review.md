# サイクル 07 の計画レビュー：M48・M49・M47・M50 と、M33・M41 の残り

この文書は、`implementation-plan.md` の M48・M49・M47・M50 と、M33・M41 の「残り（サイクル 07）」を 2 系統の独立したレビュー（Claude と Codex）にかけ、指摘を計画に反映した記録である。M48 から着手する担当者と、計画をレビューする人が読む。担当者は、計画の節が「なぜこう書いてあるか」をここで引ける。

サイクル 07 に入るのは、サイクル 06 の改善の探索で起こした M48・M49 と、サイクル 06 から移した M47・M33 の残り・M41 の残りである。作者は 2026-10-14 に、サイクル 06 の終わりの問い（`plans/cycle-06/author-decisions.md`）に答えた。取りまとめ役は、レビューに出す前に、答えを節に書いた（`81e614c`）。OI-187（見出しで 2 つ目からの列を足す）は M47 に、OI-190（名前の列の照合順序 `ja-x-icu`）は M49 に、OI-192（取消済の伝票の合計に「取消」）は M33 の残りに書いた。OI-186（流用元が並べるほかの列）は、出荷依頼の受注番号が出荷から結べず、イベントで写すことになったので、M47 に入れずに M50 として起こした。

初回のレビューは `81e614c` を読んだ。依頼には読む版の commit を書き、その版を展開したディレクトリだけを読ませた。2 系統とも Conditional Go で、High を合わせて 4 件挙げた（Claude 1 件、Codex 3 件）。High を直した版（`b90406c`）を 2 系統で読み直した（読み直し 1）。結果は末尾の「読み直し 1」にある。Claude のサブエージェントは、最終報告を返さずに終わり、依頼に書かせた結果のファイルから読んだ（`guides/dev-cycle.md`「独立したレビュアー」）。Codex は、展開したディレクトリが git のリポジトリでないために 1 回目の呼び出しが始まらず、`--skip-git-repo-check` を付けて同じ依頼を流した。一時の失敗ではないので、出し直しには数えない。

読む順は、マイルストーンの分け方 → マイルストーンごとの判定 → 指摘ごとの対応 → 作者に渡すもの → 直さなかった指摘と台帳に積んだもの、である。指摘の出典は次の形で示す。2 系統の ID がぶつかるときは、`Codex M47-1` のように系統を添える。

| | Claude | Codex |
|---|---|---|
| 初回 | `<マイルストーン>-<番号>`（`M50-1` など） | `<マイルストーン>-<番号>` |
| 読み直し 1 | `R1-<マイルストーン>-<番号>` | `R1-<マイルストーン>-<番号>` |

## マイルストーンの分け方

| マイルストーン | 中身 | 分けた理由 |
|---|---|---|
| M48 CI で依存の木を確かめ、イメージの組み立てを PR のたびに流す | `frontend` のジョブの `npm ls --all`、`image_inputs` を外す、`publish` の `skipped` の守り、壊し方の型の試行（IB-17） | サイクル 06 の改善の探索で、IB-104・IB-113 を 1 つにまとめた |
| M49 文字列の列の照合順序を決め、別の DB の worktree で `bin/ci` を流せるようにする | 品目コードの列を `pg_c_utf8`、名前の列（`tenants.name`・`items.name`・`item_labels.name`）を `ja-x-icu` にするマイグレーション、`logging_spec.rb` の親のファイル | サイクル 06 の改善の探索で IB-77・IB-110 をまとめた。OI-190 の名前の列も、同じ照合順序の決め方とマイグレーションの形なので、ここに足した |
| M47 複数の列で並べる | `Page` の複数の列の keyset、`thenBy`、かんばんの並び、見出しの Shift の操作（OI-187） | サイクル 06 の計画レビューで起こした。OI-187 の画面の操作は `thenBy` を使う画面なので同じマイルストーンに入れた |
| M50 品目と出荷依頼の一覧を、流用元が並べるほかの列でも並べる | 品目の単位・単価・安全在庫、出荷依頼の受注番号・出荷予定日の列、受注番号を「出荷可能」で運んで写す形と作り直し（OI-186・OI-193） | 台帳の反映先は M47 だったが、受注番号の写しが、イベントの項目・表の列・作り直し・一致の spec を伴い、M47 の土台の変更と合わせると 1 回の作業の大きさを超える。M47 の後に置き、足した列にも Shift の操作が効くようにした |
| M33 の残り | OI-178 の取消依頼のボタン、OI-192 の取消済の伝票の合計、OI-177 の作者の指摘 | サイクル 06 で移した。OI-177 の答えが無くても、OI-178・OI-192 は作れる |
| M41 の残り | 作者の実機の手順（OI-196） | 作者を待つだけで、取りまとめ役が作るものは無い |

実装の順は M48 → M49 → M47 → M50 → M33 の残りで、M41 の残りは作者の結果が書かれたときに片付ける。M48・M49 を先に置くのは、改善の探索で採用した変更をサイクルの最初に置く規則（`guides/dev-cycle.md`「全体の流れ」）による。M49 を M47 の前に置くので、M47 と M50 の名前の列の並びは、照合順序を決めた後の形で書ける。

サイクル 07 は 6 つで、1 つのサイクルの上限に収まる。6 つのうち M41 の残りは作者を待つだけで、M33 の残りの OI-177 も作者の指摘を待つ。待ちを含めて 6 つであり、待ちの行が片付くまで、そのマイルストーンを終えたと記録しない（Codex の違和感）。

## 判定

| マイルストーン | 初回 Claude | 初回 Codex |
|---|---|---|
| M48 | Go | Conditional Go |
| M49 | Go | Go |
| M47 | Go | Conditional Go |
| M50 | Conditional Go | Go |
| M33 の残り | Go | Go |
| M41 の残り | Go | Go |

全体の判定は、2 系統とも Conditional Go だった。Codex は M50 を Go としたが、Claude の High（M50-1）と同じことを Medium（Codex M50-2）で挙げたので、重大度は高い方を採った。High を直した版を、読み直し 1 に出した。

2 系統が同じことを挙げた指摘は次の 4 つである。

- M50 の `UNIT_PRICE` のカーソルの型が決まっておらず、`:integer` では `bigint` の単価のカーソルを拒む（Claude M50-1 は High、Codex M50-2 は Medium）
- M49 の、公開の配置は毎日作り直すので ICU の照合順序の版の食い違いに当たらないという前提と、イメージごとの確かめが足りない（Claude M49-2・Codex M49-1。どちらも Medium）
- M33 の残りで取消済の受注を E2E の世界に足すと、受注合計の example が末尾の行を「照合待ち」と期待して落ちる（Claude M33-1 は Low、Codex M33-1 は Medium）
- Shift を押した Enter で `shiftKey` が立つ根拠が無い（Claude M47-3 は Low、Codex は観点 3 の補足）

## 直さなかった指摘と、台帳に積んだもの

- 指摘は、どれも計画の直しで扱った
- 台帳の行の直し：OI-186 と OI-190 の結果の欄の反映先を、実際に書いた節（M50・M49）に直し、引当先も同じマイルストーンにした（Codex の違和感）
- 改善の候補に積んだもの：E2E の世界を複数のマイルストーンが条件付きで直すこと（Claude の違和感）を IB-114 に、Dependabot のまとめた PR の CI の時間を測ること（Claude の違和感）を IB-115 に積んだ
- 違和感のうち計画で扱ったもの：Shift を押したクリックで表の文字が選ばれること（Claude）は M47 作るもの 4 の「文字の選択」に、M50 の壊して落ちる記録が IB-17 の試行の標本に混ざること（Claude）は M50 の「M48 の壊し方の型を当てる」の文を消して扱った。待ちを含めて 6 つであること（Codex）は上の「マイルストーンの分け方」に書いた
