# サイクル 07 の逸脱検査

サイクル 07（M48・M49・M47・M50・M33 の残り）の成果物が正本から外れていないかを、2 系統のレビュアーが検査した記録である。手順は `guides/cycle-end.md`「3. 逸脱検査」にある。ここで「文書が正」と裁定した食い違いは、再発防止（`recurrence.md`）の入力になる。

レビュアーに渡したのは、サイクルの diff（`2e10f5b..6b597c9`。`6b597c9` は振り返りと知見の収穫の commit）、正本（知見の収穫で足したものを含む）、サイクルのマイルストーンの節、振り返りの「計画から実装への逆向きの照合」、実装レビューの証跡、台帳である。依頼には読む版を `6b597c9` と書き、その版を展開したディレクトリだけを読ませ、このサイクルに固有の確かめどころ（取消依頼のボタンと取消済の合計、照合順序を持たせる列と持たせない列、写しと副問い合わせの所有の条件、`thenBy` と足した列、ADR 009〜011、CI と照合順序の版の規則）を観点の下に足した（`guides/dev-cycle.md`「依頼の型」）。どちらもテストは流さず、ファイルと行を照らした。Claude のサブエージェントは最終報告を返さずに終わり、依頼に書かせたファイルから結果を読んだ。Codex は、展開したディレクトリが git のリポジトリでないので、はじめから `--skip-git-repo-check` を付けて流し、一時の失敗を起こさなかった。

## 違和感

- **振り返りが棚卸しの直しを過去形で書く**（Claude）：振り返りの逆向きの照合の 1 行目が、`handoff.md` を直したことを棚卸しの前に済んだと書いた → 振り返りは段階の順で書くので、文を「台帳の棚卸しで直す」に改め、棚卸しで直した（`inventory.md`）
- **ADR 011 の題が、品目の写しだけを言う**（Claude）：題で探す人が受注番号の写しに気づきにくい → D2 の直しで、ステータスの 1 文目にイベントで運ぶ写しを足した。題は ADR の番号と結ばれた名前なので変えない
- **出荷の計上から「出荷計上」が購買に届くまでの間、取消依頼のボタンが出る**（Claude）：非同期の連結による遅れで、正本の書き方とは一致する → 扱うことは無い
- **取消済の伝票の詳細の明細の行の文言**（Claude）：IB-126 にある
- **作り直しのタスクが 2 つの写しを同じトランザクションで作り直す**（Claude）：IB-124 にある
- **在庫の単体のコメントの位置**（Codex）：`stocks_spec.rb` の安全在庫の設定を説明するコメントが、足した `safety_stocks_sql` の example の直前に残る → spec の書き方の直しで小さく、IB-129 に積んだ
- **明細の行の文言と、Chromium の外の Shift の操作**（Codex）：IB-126・IB-121 にある

## 再発防止へ渡すもの

「文書が正」の裁定は無い。D2・D3 は、M50 が足した判断と公開 API を、取り込んだ正本の別の節に写し切らなかったもので、知見の収穫と逸脱検査で捕まった。D3 と同じ形（「1 つの公開 API に集める」と書いた節に、同じ表への別の入口を足した）は、振り返りの「複数の箇所に当てるべき修正を、一部にだけ当てた」に当たるので、再発防止で扱う（`recurrence.md`）。
