# サイクル 09 の逸脱検査

サイクル 09（M52・M53・M54・M55）の成果物が正本から外れていないかを、2 系統のレビュアーが検査した記録である。手順は `guides/cycle-end.md`「3. 逸脱検査」にある。ここで「文書が正」と裁定した食い違いは、再発防止（`recurrence.md`）の入力になる。同じ依頼で、サイクル末のブランチで行った M56（担当を止める手順を 1 か所にする）と知見の収穫の正本の直しの実装レビューも頼んだ。その結果は `implementation-reviews.md` の M56 の節にある。

レビュアーに渡したのは、サイクルの diff（`081a134..ac957e2`。`ac957e2` は知見の収穫の commit）、サイクル末のブランチの diff（`c35a702..ac957e2`）、正本（知見の収穫で足したものを含む）、サイクルのマイルストーンの節（M52〜M56）、振り返りの「計画から実装への逆向きの照合」、実装レビューの証跡、台帳である。依頼には読む版を `ac957e2` と書き、その版を展開したディレクトリだけを読ませ、このサイクルに固有の確かめどころ（M54 の同期化と「出荷可能」の例外、M53 の進みの出来事と時刻、M55 の在庫の品目の確かめと `SqlSubquery`、消した停止の表と請求対象明細の冪等キー、公開 API の戻り値と操作者のいない入口の表、ADR 012 と ADR 010・011 の整合、M52 の 3 つのガード）を観点の下に足した（`guides/dev-cycle.md`「依頼の型」）。どちらもテストは流さず、ファイルと行を照らした。Claude のサブエージェントは最終報告を返さずに終わり、依頼に書かせたファイルから結果を読んだ。Codex は `--skip-git-repo-check` を付けて流し、一時の失敗を起こさなかった。

## 違和感

- **実装レビューの証跡の冒頭は「Codex は差分とリポジトリを読み、手元でコマンドを流して確かめる」と書くが、4 つのマイルストーンのどれでも Codex は spec を流していない**（Claude）→ 証跡はその時点の記録なので直さない。振り返りの想定外 6 で、再発防止が `dev-cycle.md`「独立したレビュアー」を直した（`recurrence.md`）
- **列を消した後の `ignored_columns` を外す時機が、どの文書にも無い**（Claude）→ IB-151 に積んだ
- **出荷指示の取消のロックの順が、ADR 012 と `data-model.md` のロックの順の文に無い**（Claude）→ 順は計上の部分列でデッドロックはしない。IB-152 に積んだ
- Codex は、どちらの段階でも「なし」だった

## 再発防止へ渡すもの

「文書が正」の裁定のうち、再発防止で扱うのは D1・D2 である。D1 は、完了条件が「参照だけ」と求めた範囲を、作った者が手順の節の中だけと読み、ほかの文書の同じ手順を数えなかったもの、D2 は、実装の途中で計画の節に書き足した決めを `judgment` に登録しなかったもので、サイクル 08 の想定外 8 と同じ種類である。D3・D4 は台帳の閉じ忘れで、サイクル末の中で直した（`recurrence.md`）。
