# サイクル 09 の振り返り

サイクル 09（M52・M53・M54・M55・M33 の残り・M41 の残り）の計画が実装にどれだけ合っていたかと、回し方そのものが働いたかを評価した記録である。手順は `guides/cycle-end.md`「1. 振り返り」にある。ここで挙げた想定外は、知見の収穫（`harvest.md`）と再発防止（`recurrence.md`）の入力になる。

読んだものは、計画レビューの証跡（`plan-review.md`）、実装レビューの証跡（`implementation-reviews.md`）、サイクルの commit の履歴（`081a134..c35a702`）、計画の節を直した commit、台帳 2 本、`handoff.md` である。取りまとめ役が担当とレビュアーを動かしたときに見たことは、リポジトリに残らず、この振り返りの入力にも無いので、ここには書いていない。

## サイクルの終わり方

サイクル 09 は、計画レビューの時点の 3 つ（M52・M33 の残り・M41 の残り）から、上限の 6 つになって終えた。M53・M54 は M52 の計画レビューの後に作者の判断（OI-210・OI-211）で、M55 は M53・M54 の計画レビューの後に作者との責務と関心の分離の監査の判断（OI-215〜OI-218）で足した（想定外 1）。足した 3 つは、どれも計画レビューに通してから実装した。

M56（担当を止める手順を 1 か所にする、OI-208）は、サイクル末の担当がこのブランチで行う作業で、サイクル 09 のマイルストーンの数に数えない（OI-221）。この振り返りを書いた時点（`c35a702`）では未着手なので、評価の対象に入れない。OI-208 の引当先は M52 → M54 → M56 と 2 度移った（想定外 2）。

M33 の残りは、作者の画面の指摘（OI-177、`open`）が来ていないので、作るものが無かった。M41 の残りは、作者の実機の手順の結果（OI-196、`blocked-user`）を待つだけだった。`bin/check-open-items --due M33` は OI-177 の 1 行で、`--due M41` は OI-196 の 1 行で落ちる。どちらも残りだけを次のサイクルへ移す（台帳の棚卸し）。M41 の残りを移すのは、サイクル 06 から数えて 5 回目で、作者の答え（IB-133、毎サイクル移し続ける）のとおりである。

## 回し方の改善の提案

`guides/dev-cycle.md` か `guides/cycle-end.md` への変更として書く。機械で止められるものは、再発防止（段階 4）で検査や設定を直すので、ここでは提案だけを書く。

1. **次のサイクルの最初のブランチを切る前に、取りまとめ役が、そのブランチの土台が main の先端を祖先に持つかを確かめる。持たなければ、取りまとめ役が main をマージしてから計画を書く**（`dev-cycle.md`「3. サイクル末」の、次のサイクルの最初のブランチをサイクル末の PR のブランチから切る段落と、「ブランチと PR」）。担当の環境では main のマージが拒否されるので、取り込みを担当に任せない。想定外 2 の予防で、サイクル 08 の想定外 10 にも当たる
2. **読み直しの上限を `dev-cycle.md`「判定の形」に書く。取りまとめ役は、同じ守りに 2 回続けて High が出たら、指摘の形を足さずに照らし方そのものを計画に戻して決め直す**。迂回の形を並べて落とす照らし方は、並べた形の外に穴が残る。上限で High の直しが残ったときは、直しを読み直しに出せないことと、閉じたことを確かめた壊し方を証跡に書く。想定外 3 の予防である
3. **計画を書く者は、壊して落ちる記録の表に、同じ条件を 2 つの守り（RLS と scope など）が持つ行を書くときは、落ちる example がどちらの守りを通らない経路かを書く。計画レビューは、表の壊し方が流せる形か（YAML のタグになる式など）を観点 3「実現できるか」で見る**（`dev-cycle.md`「1. 計画レビュー」）。想定外 5 の予防である
4. **取りまとめ役は、Codex を読み取り専用で立てると DB と一時ファイルを使えず spec を流せないことを `dev-cycle.md`「独立したレビュアー」に書き、どちらの系統も spec を流さなかったときは、実装レビューの節にそのことを書く**。証跡の冒頭の「手元でコマンドを流して確かめる」は、この事実に合わせる。想定外 6 の予防である
5. **`open` のままの行に作者の判断や取りまとめ役の指示を書く場所（内容の欄）を、`dev-cycle.md`「残件の台帳」に書く**。想定外 10 の予防である
6. **取りまとめ役は、計画レビューの証跡に、マイルストーンごとに 5 つの観点の「指摘」か「指摘なし」を書く**（`dev-cycle.md`「判定の形」の「指摘が無くても、判定と観点ごとの『指摘なし』を証跡に残す」を、計画レビューの証跡にも当てる）。上の「回し方の各段階の成果物」で欠けた成果物である
7. 層ごとの責務をレビューの観点から名指しすることは、M55 の作るもの 4 が済ませた（想定外 1）。足すものは無い
