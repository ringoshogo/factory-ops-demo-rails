# サイクル 09 の再発防止

サイクル 09（M52・M53・M54・M55 と、サイクル末の M56）で直し終えた指摘と食い違いの原因をたどり、同じ種類が再び起きない仕組みを足した記録である。手順は `guides/cycle-end.md`「4. 再発防止」にある。直すこと（是正）は各マイルストーンと逸脱検査で済んでいるか、行き先を決めてあるので、ここでは予防だけを扱う。知見の収穫（`harvest.md`）に書いた知見は、ここに書かない。

読んだものは、実装レビューの指摘（High の 4 件、Medium と、振り返りで 2 回以上と数えた種類の Low）、逸脱検査の裁定（`conformance.md`。「文書が正」は D1〜D4）、M56 の実装レビュー（`implementation-reviews.md` の M56 の節）、振り返りの想定外と回し方の改善の提案、サイクル 08 の再発防止（`cycle-08/recurrence.md`）である。指摘は、振り返りの「指摘の数」の種類ごとにまとめ、まとめた行に出どころを挙げた。

## 検査を足した記録

`bin/check-open-items` の 2 つの検査は、`spec/bin/check_open_items_spec.rb` に example を先に足し、期待の不一致で落ちることを見てから実装した（RED：11 examples, 2 failures。どちらも、検査の無い版が成功で終わり `expect(status).not_to be_success` で落ちた。`d8676c2`）。最初の版の壊し方（「判断なし」と `OI-NN` を受け付けない、節の外も確かめる、サイクル 09 も確かめる、観点を確かめない、観点を文書の全体から集める）は、どれも落ちた。

改善の探索と同じ依頼で 2 系統に実装レビューを頼み（`improvement.md`「再発防止で足した検査の実装レビュー」）、どちらも Go だった。Medium の指摘（どの `OI-NN` でも通る、箇条の続きの行・節の中の深い見出し・コードの囲みを扱わない、本物の `dev-cycle.md` とサイクル 11 からの対照が無い、`dev-cycle.md` が無いと例外で止まる）を直した。直しの example も先に足し、期待の不一致で落ちることを見た（13 examples, 2 failures。本物の `dev-cycle.md` の example は書いた時点で通ったので、下の C8 で代えた）。直した後に、次の壊し方で落ちることを確かめ、元に戻した。

| 壊し方 | 結果 |
|---|---|
| C1：字下げした続きの行を、前の項目に足さない | 1 failure（実装レビューの証跡の example。続きの行の `OI-NN` を読まない） |
| C2：`judgment` か `decided` の行でない ID でも通す | 1 failure（同上。`open` の行の ID の項目を通す） |
| C3：コードの囲みの中の行も読む | 1 failure（同上。囲みの中の `#` で節が閉じる） |
| C4：節の中の深い見出しで節を閉じる | 1 failure（同上。深い見出しの下の項目を見逃す） |
| C5：サイクル 11 からにする | 3 failures（計画レビューの 3 つの example） |
| C6：サイクル 10 だけを確かめる | 1 failure（サイクル 11 の実装レビューの証跡の example） |

証跡はその時点の記録なので、検査はサイクル 10 からの証跡にだけ当てる。サイクル 09 以前の証跡を書き換えずに済み、書く者は新しい形を最初の証跡から使う。「判断なし」と書けば必ず通るので、決めたことかどうかを書く者に選ばせる形の限界は残る。次のサイクル末の逆向きの照合で、「判断なし」と書いた項目に決めたことが混ざっていないかを数え、この検査が効いたかを測る。
