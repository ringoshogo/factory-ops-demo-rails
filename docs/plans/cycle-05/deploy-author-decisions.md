# 一覧の並べ替えと公開の配置で作者が決めること

サイクル 05 の計画レビューで、作者の判断（OI-07 一覧の並べ替え、OI-14 Raspberry Pi の k3s への配置）を計画に落としたところ、作者が決める点が 6 つ出た。計画はどれも既定の案を置いて書いてあり、実装は既定で進めてよい。作者は各項目で「既定のまま」か「変える」かを決める。決まった答えはコーディネーターが台帳（`open-items.md` の OI-144〜OI-149）に先に書き、担当はそれを読む。

答え方：全部既定でよければ「全部既定で」。変えるものがあれば、番号と変えたい形を書く。項目 4 だけは、Raspberry Pi で `free -h` を流した値を知らせてほしい。

## サイクル 05 の流れ

サイクル 05 は、次の順に作る。各項目は、どのマイルストーンに効くかの順に並べた。

1. M38：テストの穴を塞ぐ（作者の判断は要らない。いま実装中）
2. M39・M40：一覧の API に件数・並べ替え・絞り込みを足す（項目 1）
3. M33：画面を写す（項目 1 の答えで並べ替えの見出しが決まる）
4. M41：Raspberry Pi の k3s に配置して公開する（項目 2〜6）

## 1. 一覧の並べ替え（OI-144、M33 の前まで）

- **何が問題か**：一覧の API で並べ替えに使える列を、どこまで広げるか。
  - 受注一覧なら、受注の表にある列（受注日・受注番号など）では素直に並べられる。
  - 取引先の名前・金額の合計・状況・在庫の品目のコードと名前は、別のコンテキストの表にあるか、計算で出す値である。これで並べるには、相手の表を結合するか、相手の公開 API から並びを受け取る必要があり、コンテキストの境界を越える。
  - 流用元の画面は、これらの値で並べ替え、複数の列でも並べる。在庫の画面には品目の検索の欄がある。
- **既定**：並べ替えは一覧の表の列に限り、1 つの列だけで並べる。状況はタブと絞り込み（M40）で見分ける。在庫の画面には品目の検索の欄を置かない。
- **変えるなら**：並べたい値（取引先の名前や品目の名前など）を一覧の表に写す列を足し、その列で並べ替えと検索をできるようにする。足すだけの変更なので、M39 は既定で進め、後から足せる。どの画面のどの値で並べたいかを知らせてほしい。

## 2. 公開のホスト名（OI-145、M41）

- **何が問題か**：公開する画面の URL を決める。Cloudflare Tunnel の公開のホスト名、k3s の Ingress、Rails の許可するオリジンがこの値になる。
- **既定**：流用元と同じドメインの下の `factory-ops-rails.hayatec.dev`。
- **変えるなら**：使いたいホスト名を知らせる。

## 3. 毎日の作り直しの時刻（OI-146、M41）

- **何が問題か**：訪問者全員が同じデータを使うので、毎日決まった時刻にシードから作り直す。作り直しの数分は、画面が API に届かない。流用元は Raspberry Pi を夜に止める運用にしており、止めている間に時刻を過ぎると作り直しが流れない。
- **既定**：日本時間の 4:30 に作り直す。流用元のリセット（4:00）と重ねないためである。Raspberry Pi を止めていて時刻を過ぎても、時刻から 6 時間の内に起動すれば、起動の後に流す。
- **確かめたいこと**：Raspberry Pi をいまも夜に止めているか。作り直しの時刻を変えたいか。

## 4. Raspberry Pi の機種とメモリ（OI-147、M41）

- **何が問題か**：同じ Raspberry Pi に流用元と本デモの 2 つが載る。本デモは Rails・ジョブのワーカー・Next.js・PostgreSQL の 4 つが常に動き、メモリの上限の和は約 1.9GiB になる。流用元と k3s を足すと 3GiB 前後になる。機種とメモリはどの文書にも書かれていない。
- **既定**：8GB の機種とみなし、見積もりのまま置く。
- **知らせてほしいこと**：Raspberry Pi で `free -h` を流した値と機種。4GB なら、上限を下げるか、ジョブのワーカーを Web のプロセスの中で動かす形に変える。

## 5. 訪問者に許す操作（OI-148、M41）

- **何が問題か**：全員が同じデータを使うので、ある訪問者の操作が次の作り直しまで全員の画面を変える。とくに次の操作が効く。
  - 取引関係の失効・権限の撤回：相手の会社の画面からカタログや発注が消える
  - 受注の取消・請求書の確定：後の流れが進められなくなる
  - 5 万行までの CSV の取り込み：Raspberry Pi の CPU を使い、ほかの訪問者が遅くなる
  - ログインの画面には `admin` のアカウントも並ぶので、`admin` に限る操作も誰でも試せる
- **既定**：すべての操作を許し、毎日の作り直しで戻す。デモとして全部の機能を触ってもらえる。
- **変えるなら**：公開の配置で止める操作を選ぶ。例：失効と撤回だけ止める、取り込みの行数の上限を下げる。

## 6. 共有アカウントのログアウト（OI-149、M41）

- **何が問題か**：いまのログアウトは、同じユーザーのほかのセッションもすべて切る（盗まれた Cookie を無効にするための安全策）。公開の配置では全員がログインの画面に並ぶ同じアカウントを使い、画面は会社を切り替えるのにログアウトする。そのため、1 人がログアウトすると、同じアカウントで見ているほかの訪問者が全員ログインの画面に戻される。
- **既定**：公開の配置でだけ、ログアウトでほかのセッションを切らず、自分の Cookie を消すだけにする（設定 `SHARED_DEMO_ACCOUNTS=1`）。手元と本来の運用では、いまの安全策のままにする。このとき、ログアウトの前に写し取られた Cookie は使えるままになるが、共有のデモのアカウントなので守るものは無い。
- **変えるなら**：公開の配置でも、いまのまま全セッションを切る。訪問者がときどきログインの画面に戻されることを受け入れる。
