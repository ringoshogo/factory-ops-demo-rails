# サイクル 05 の振り返り

サイクル 05（M38・M39・M40・M33・M41）の計画が実装にどれだけ合っていたかと、回し方そのものが働いたかを評価した記録である。手順は `guides/cycle-end.md`「1. 振り返り」にある。ここで挙げた想定外は、知見の収穫（`harvest.md`）と再発防止（`recurrence.md`）の入力になる。

読んだものは、計画レビューの証跡（`plan-review.md`）、実装レビューの証跡（`implementation-reviews.md`）、サイクルの commit の履歴（`0f84d5d..7bbe572`）、計画レビューの後に `implementation-plan.md` を直した commit、台帳 2 本、PR #55〜#60 の本文と CI の記録、作者に示した判断の説明（`m33-author-decisions.md`・`deploy-author-decisions.md`）である。取りまとめ役が担当とレビュアーを動かしたときに見たこと（CI の待ち方、レビュアーの終わり方、作業ツリーの使い方）は、リポジトリに残らないので、ここに書いた。

## M33 と M41 を閉じずにサイクル末に入ったこと

M33 と M41 は、実装と実装レビューを終えたが、作者の判断と作者だけができる確かめが残り、`bin/check-open-items --due` を通せない。M33 は OI-144（並べ替えの列を一覧の表に限るか）と、作者が受け入れのときに後で出すとした画面の細かい指摘（OI-177）を、M41 は OI-145〜OI-149（ホスト名・作り直しの時刻・機種とメモリ・訪問者に許す操作・共有のアカウントのログアウト）と、作者の実機の手順（`deploy/README.md`「作者の手順」）を待つ。どれも既定で作ってあり、作者の答えは値の差し替えか受け入れで、作るものの形は変わらない。

`guides/dev-cycle.md`「全体の流れ」の移し方は、作者の判断を待って**着手できない**マイルストーンを次のサイクルへ移すと書き、着手して実装レビューまで終えたが閉じられないマイルストーンを書いていなかった。取りまとめ役は、M33 と M41 を実装レビューの節があるサイクル 05 のマイルストーンとして数え、作者を待つ残りだけをサイクル 06 の表へ移した。待つ間は、M38〜M41 で分かったことが正本へ戻らないからである。移し方の規則は、再発防止で `dev-cycle.md`「全体の流れ」と `cycle-end.md`「開始の確認」に書いた（`recurrence.md`）。

作者は、このサイクル末の間に 2 つを決めた。リポジトリを public にした（OI-06 を closed）。M33 の検収表のスクリーンショットを受け入れた（`implementation-reviews.md`「M33 フロントエンド」の「残件の処理」）。

## 回し方の改善の提案

`guides/dev-cycle.md` か `guides/cycle-end.md` への変更として書く。機械で止められるものは、再発防止（段階 4）で検査や設定を直すので、ここでは提案だけを書く。

1. **CI の時間の予算を決め、重いジョブを流す条件を絞る**（`guides/config.md`「CI の工程」、`.github/workflows/ci.yml`）。PR の CI は、最も長いジョブで 10 分の内に終える。`images` のジョブは、イメージに入るものを変えた PR と main への push でだけ流す
2. **CI を待つ担当は、`gh pr checks --watch` をフォアグラウンドで流して待つ**（`dev-cycle.md`「ブランチと PR」）。作業の区切りで止まって待たない
3. **レビュアーへの依頼は、結果をファイルに書いて終えることだけを求め、立てた者はレビュアーが終わるまで自分を終えない**（`dev-cycle.md`「独立したレビュアー」）
4. **`bin/setup` は、すでに応える DB を使い、ロールを psql で作る**（`bin/setup`、`guides/bin.md`「bin/setup で変えたこと」）。worktree の担当が `bin/ci` を 1 つで流せるようにする
5. **E2E の Rails は、rspec と別のファイルにイベントのログを書く**（`config/initializers/event_log.rb`）。同時に流さない規則を文書から外す
6. **作者の判断を待って閉じられないマイルストーンの扱いと、答えを求める時機を決める**（`dev-cycle.md`「全体の流れ」・「1. 計画レビュー」、`cycle-end.md`「開始の確認」）。計画レビューで起こした `blocked-user` の行を、作るものが変わる問いと、値の差し替えか受け入れの問いに分ける。前者は着手の前に答えを待ち、後者は既定で作って、答えを待つ残りだけを次のサイクルへ移す
