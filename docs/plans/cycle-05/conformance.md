# サイクル 05 の逸脱検査

サイクル 05（M38・M39・M40・M33・M41）の成果物が正本から外れていないかを、2 系統のレビュアーが検査した記録である。手順は `guides/cycle-end.md`「3. 逸脱検査」にある。ここで「文書が正」と裁定した食い違いは、再発防止（`recurrence.md`）の入力になる。

レビュアーに渡したのは、サイクルの diff（`0f84d5d..ec4dfc8`。`ec4dfc8` は知見の収穫の commit で、再発防止の仕組みを先に入れたものを含む）、正本（知見の収穫で足したものを含む）、サイクルのマイルストーンの節、振り返りの「計画から実装への逆向きの照合」、台帳である。依頼には読む版を `ec4dfc8` と書き、その版を展開したディレクトリだけを読ませた（`guides/dev-cycle.md`「依頼の型」）。どちらもテストは流さず、ファイルと行を照らした。Codex は、`image_inputs` の `pattern` を取り出して `grep -qE` で当たり外れを確かめた。Claude のサブエージェントは最終報告を返さずに終わり、依頼に書かせたファイルから結果を読んだ。

## 違和感

- **収穫の commit が持ち込んだ private の前提**（Claude）：`config.md`「CI の工程」に足した予算の理由が「private の間は利用の枠も使う」を含んでいた。リポジトリは同じ日に public になった。理由を「担当が結果を待つ時間」だけにした
- **前の形を意味で集める照合**（Codex）：振り返りの逆向きの照合は本番の環境の条件を README と spec のコメントに当てたが、資格情報の渡し先とログアウトの例外（D1〜D3）と `db/seeds.rb`（D11）が残った。M41 の「文書に残すこと」が直す箇所を数えて名指ししたので、名指しの外が残った → 再発防止で扱う（`recurrence.md`）
- **ロールの属性の確かめ**（Claude）→ IB-96
- **画面の TypeScript 以外のファイルのコメントの検査**（Claude）→ IB-97
- **ダッシュボードの安全在庫の 100 件の上限**（Claude）→ IB-98
- **受注側の視点の借用**（Claude）→ IB-95
- **安全在庫の条件のもう 1 か所**（Claude）：値の印（`stocks.rb` の `available < safety_stock`）は件数に使わないので、集計と一覧は食い違わない。等しいときの単体が無いことは、印を変えるときの実装レビューの観点 4 で見る。積まない
- **`jobs` の接続プールの数え方**（Claude）：計画 M41 の表は足す数を書かないが、`config.md` と spec が 4 を足して 20 にしている。値は spec が守るので直さない
- **Node の版の書き方**（Claude）：README と CI のコメントの「engines と同じ 22 系」を、`engines` は 22.12 以上で CI は 22 系、に直した
- **画面の単体の置き場と、公開の配置の Web の起こし方**（Claude）：`testing.md` に `scripts/**/*.test.mjs` を、`bin.md`「本番のコンテナが使うもの」に公開の配置の違いを書いた
- **`images` の push がテストの成功を待たない**（Codex）：IB-91 にある
- **M33・M41 の作者の判断と実機の確かめ**（Codex）：この検査は公開の受け入れを意味しない。OI-144〜OI-149 と実機の手順で追う

## 再発防止へ渡すもの

「文書が正」の裁定は D3・D10・D11 の 3 つである。D3 と D11 は、M41 が変えた振る舞い（共有のアカウントのログアウト、本番の環境の世界の作り方）の前の形が、計画の「文書に残すこと」が名指ししなかったコメントに残ったもので、振り返りの逆向きの照合の 1 つ目と同じ種類である。D10 は、規約が名指しした対象（Dockerfile とその無視の一覧）を、規約を実装した側（ワークフローの `pattern`）が拾いきれず、それを確かめるものが無かった。
