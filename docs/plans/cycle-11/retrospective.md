# サイクル 11 の振り返り

サイクル 11（M58・M33 の残り・M41 の残り）の計画が実装にどれだけ合っていたかと、回し方そのものが働いたかを評価した記録である。手順は `guides/cycle-end.md`「1. 振り返り」にある。ここで挙げた想定外は、知見の収穫（`harvest.md`）と再発防止（`recurrence.md`）の入力になる。

読んだものは、計画レビューの証跡（`plan-review.md`）、実装レビューの証跡（`implementation-reviews.md`）、サイクルの commit の履歴（`964d4e1..41b601c`）、計画の節を直した commit、台帳 2 本、`handoff.md` である。取りまとめ役が担当を動かしたときに見たことのうち、取りまとめ役がこのサイクル末の担当への依頼に書いた事実（一時の DB の後始末、担当が拒まれたコマンド、取りまとめ役との行き違い）は入力に入れ、どの事実が依頼から来たかを書いた。

## サイクルの終わり方

サイクル 11 は、計画レビューの時点の 3 つ（M58・M33 の残り・M41 の残り）のまま終えた。計画の数の空き（上限 6 に対して 3）に挙がった改善の候補 IB-158・IB-159 は、作者が 2026-10-21 に、サイクル 11 に足さず、サイクル末の改善の探索で裁定すると決めた（取りまとめ役の依頼）。

## 回し方の改善の提案

`guides/dev-cycle.md` か `guides/cycle-end.md` への変更として書く。機械で止められるものは、再発防止（段階 4）で検査や設定を直すので、ここでは提案だけを書く。

1. **完了条件の `git grep` を流した版の commit を、件数とともに証跡に書かせ、`bin/check-open-items` が確かめる**。「完了の判定」の文に commit を書くことを足し、検査を次のサイクルからの証跡で件数の注釈に commit の SHA を求める形にする。最後の commit は自分の SHA を書けないので、流した commit と「この後の commit は証跡だけを変える」を書く（M58 の証跡の形）。想定外 3 の予防である
2. **積み重ねたブランチで手元の `bin/ci` を流すときの `BASE_REF` を決める**（`dev-cycle.md`「ブランチと PR」）。前の段のブランチを渡し、前の段がマージされてブランチが消えたら `origin/main` を渡す。想定外 1 の予防である
3. **完了条件の `git grep` が `docs/implementation-plan.md` を除くときは、計画のほかの節に、替えた規則や形を前提にした文が残らないかを別に数える**（`dev-cycle.md`「完了の判定」）。想定外 2 の予防である
4. **担当が取りまとめ役に送った問いへの答えも、受け口のファイルに書く**（`dev-cycle.md`「残件の台帳」）。想定外 5 の予防である
5. サイクル末のブランチを最後のマイルストーンの先端から切ったこと（「サイクルの終わり方」）と、想定外 4 は、規則と道具のとおりに働いた。足すものは無い
