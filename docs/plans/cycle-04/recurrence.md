# サイクル 04 の再発防止

サイクル 04（M37・M30・M31・M32）で直し終えた指摘と食い違いの原因をたどり、同じ種類が再び起きない仕組みを足した記録である。手順は `guides/cycle-end.md`「4. 再発防止」にある。直すこと（是正）は各マイルストーンと逸脱検査で済んでいるので、ここでは予防だけを扱う。知見の収穫（`harvest.md`）に書いた知見は、ここに書かない。

読んだものは、実装レビューの指摘（High は M37 R1 と M31 R1、Medium と、振り返りで 2 回以上と数えた種類の Low）、逸脱検査の食い違い（`conformance.md`。「文書が正」の D1 と、違和感の 1 つ目）、振り返りの想定外と回し方の改善の提案、サイクル 03 の再発防止（`cycle-03/recurrence.md`）である。指摘は、振り返りの「指摘の数」の種類ごとにまとめ、まとめた行に出どころをすべて挙げた。

## 機械にした検査と、壊して落ちることの確かめ

どの検査も、先に spec を書いて落ちることを見てから、実装を直した。壊したファイルは複製から戻し、戻すときに更新時刻を進めた。

| 検査 | RED | 壊し方と落ちたもの |
|---|---|---|
| `spec/matrix/cross_read_spec.rb`「spec と補助は `MatrixCrossRead.remove!` を直に呼ばない」 | 補助を直す前に流し、`spec/matrix/cross_read_spec.rb`・`spec/matrix/matrix_world_spec.rb`・`spec/support/cross_read.rb`・`spec/support/matrix_world.rb` の 4 つが直の呼び出しとして挙がって落ちた（1 example, 1 failure） | `spec/matrix/cross_read_spec.rb` に `after(:context) { MatrixCrossRead.remove! }` を持つグループを足すと、そのファイルが挙がって落ちる |
| `MatrixCrossRead.share` の、足し終えたときだけ外す判定 | 補助を移しただけで判定は前と同じなので、既存のガードで確かめた | `share` の外すフックから `if` を外すと、`cross_read_spec.rb` と `matrix_world_spec.rb` の「同じ名前のポリシーがすでにあれば…あったポリシーを外さない」の 2 件が落ちる |
| `MatrixCrossRead.with_policies` の、足すのに失敗したら外さない判定 | 新しい example「with_policies は、足すのに失敗したら、先にあったポリシーを外さずに送出する」を足して通した | `add!` を `begin` の内側に入れると、その example が落ちる |
| `spec/scenarios/demo_world_spec.rb`「DemoWorld は、admin に限る公開 API を Operations の外から呼ばない」（逸脱検査 D1） | `DemoWorld` に `Billing::Closing.discard` の呼び出しを一時に足し、直す前の spec は 1 example, 0 failures で通り、直した後の spec は `got: [["Billing::Closing", :discard]]` で落ちた | 呼び出しを外すと 13 examples, 0 failures |

補助を替えた後に、行列とテナントの強制と、共有の文脈を使う spec をまとめて流し、通った（`bundle exec rspec spec/matrix spec/db/tenant_enforcement_spec.rb` で 1319 examples, 0 failures、共有の文脈を使う 9 ファイルで 563 examples, 0 failures）。世界を開く前にポリシーを足し、世界を閉じた後に外す順は、`share` を世界のフックより先に登録することで決まる（rspec-core 3.13 の `after` は登録の逆の順に走る。`lib/rspec/core/hooks.rb` の `after` が `:prepend` で登録する）。順を逆にする壊し方は、外すフックが世界のトランザクションのロックを待って終わらないので、流していない。
