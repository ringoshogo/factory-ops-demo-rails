## 違和感

- **ポリシーの足し外しの example が、直す前の形のまま残る**（Claude）：`spec/matrix/cross_read_spec.rb` と `spec/matrix/matrix_world_spec.rb` の example は、`MatrixCrossRead.add!` の後に `ensure` で `remove!` を呼ぶので、`add!` が「ポリシーがすでにある」で失敗しても、別の実行が足したポリシーを外す。振り返りの逆向きの照合の 3 つ目と同じ形で、再発防止で補助の形を直す（`recurrence.md`）
- **監査ログの入口の数え方**（Claude）：`graphql-schema.md`「監査ログ」は、書き込みが起きる入口を mutation・イベントのジョブ・取り込みのジョブの 3 つと数える。サイクル 04 で、定期のジョブ（置いたままのファイルの後始末。相手に効果は及ばない）とシードが加わった。シードは同じ段落で扱っている → IB-64 に積んだ
- **入力の上限の数え方と置き場**（Claude）：上限の表は「公開 API が上限を定数で持つ」と書くが、単価の上限はモデルの定数にある。訂正の理由の 200 文字は、前後の空白を落とす前の長さで数える → IB-65 に積んだ
- **本番で安全在庫を設定する手段が無い**（Claude）：`set_safety_stock` は本番で例外になり、GraphQL の入口も取り込みの列も無いので、本番のダッシュボードの安全在庫を下回る在庫は常に空になる。OI-125 でサインアップと同じく範囲外にしたものだが、画面の項目が本番で意味を持たないことは文書に無い → IB-66 に積んだ
- **振り返りが、まだ済んでいない棚卸しを過去形で書く**（Claude）：逆向きの照合の OI-141 は、台帳の棚卸し（段階 5）で M33 の節に書く。この PR で済ませる
- **SELECT を開いても見えない所有の条件、シードが claim しないジョブ**（Codex）：IB-60・IB-61 にある

## 再発防止へ渡すもの

「文書が正」の裁定は D1 の 1 つである。D1 は、規則（GraphQL を通らない入口は `admin` に限る操作の規則を評価してから呼ぶ）を守る spec が、規則の対象を、規則を実装した側（`Operations`）から作っていたために、実装に無い操作が検査の外に残った。違和感の 1 つ目は、振り返りの想定外 6（同じ補助の型で繰り返したポリシーの外し方）と同じ種類なので、そこで扱う。
