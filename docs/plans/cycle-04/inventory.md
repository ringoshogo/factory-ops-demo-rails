# サイクル 04 の台帳の棚卸し

サイクル 04（M37・M30・M31・M32）の終わりに、残件と改善の候補の 2 つの台帳を全部読み直した記録である。手順は `guides/cycle-end.md`「5. 台帳の棚卸し」にある。作者への一覧は、サイクル末の PR の本文の冒頭に貼る。

## 作者への一覧

作者の判断が要る `blocked-user` と、作者が不在の間に取りまとめ役が決めた `judgment` である。内容と判断の理由は `plans/open-items.md` の各行にある。作者が最初に読む問いを先に置き、残りを ID の順に並べる。

### 先に決めてほしい問い

1. **M33（フロントエンド）の著者判断 1〜8 と公開の時期（OI-06〜OI-14）**。M33 はこれを待って着手できず、サイクル 05 へ移した（`retrospective.md`「M33 をこのサイクルに入れなかったこと」）。M33 の計画（`implementation-plan.md`「M33 フロントエンド」の「著者判断」）は既定を置いてあるので、既定のままでよいかを 1 つずつ決める。既定と違う答えがあれば、M33 の節を先に直してから計画レビューに出す
2. **M33 の E2E の世界の中身（OI-138・OI-139）と、シードが監査の行を書かないこと（OI-141）**。E2E の世界は、止まっていられない状況（発注の `SENT`、取り込みの `QUEUED`・`STAGING`・`APPLYING`）の行を持たない。シードの直後の監査ログには、イベントの受信の行だけが並ぶ。どちらも M33 の画面の見え方を決めるので、M33 の着手の前に確かめる

## 残件の読み直し

`open` の 2 行を全部読んだ。要らなくなった行は無かった。改善の探索の後に、OI-143 を足した（下の表）。

| ID | 引当先 | 読み直した結果 |
|---|---|---|
| OI-17 | M33 | 画面 18 の問い合わせの書き直し。計画レビューで M33 の画面の表を取引先の一覧と 1 社のカタログに分けたが、実装は M33 で行うので残す |
| OI-142 | M33 | 逸脱検査 D3（`WEB_CONCURRENCY=0` の Web の起動）の確かめ。M33 の節の作るもの 4 に足した |
| OI-143 | M33 | 改善の探索の裁定で Claude が挙げた、E2E の世界を作る間に `bin/jobs` を起こさない順の保証。M33 の節の作るもの 4 の E2E の世界に足した |

`bin/check-open-items --due` を、サイクル 04 で終えたマイルストーン（M37・M30・M31・M32）のそれぞれで流し、すべて通った。引当先のマイルストーンを終えたのに残っている `open` と `blocked-user` は無い。`--due M33` は、OI-06〜OI-14・OI-17・OI-142・OI-143 で落ちる。M33 はまだ終えていないので、正しい。

閉じた行は無い。足した行は OI-142（逸脱検査 D3）と OI-143（改善の探索）である。引当先を後のマイルストーンにした行は、その節の作るものに ID と作業を書いた。M33 の節には、OI-142 を作るもの 4 に、OI-141 を画面 3（監査ログ）の行に書いた。OI-141 は M32 の実装レビューで M33 に送ったが、M33 の節に書いていなかった（振り返りの逆向きの照合）。
