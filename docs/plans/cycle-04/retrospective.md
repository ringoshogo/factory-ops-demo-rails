# サイクル 04 の振り返り

サイクル 04（M37・M30・M31・M32）の計画が実装にどれだけ合っていたかと、回し方そのものが働いたかを評価した記録である。手順は `guides/cycle-end.md`「1. 振り返り」にある。ここで挙げた想定外は、知見の収穫（`harvest.md`）と再発防止（`recurrence.md`）の入力になる。

読んだものは、計画レビューの証跡（`plan-review.md`）、実装レビューの証跡（`implementation-reviews.md`）、サイクルの commit の履歴（`c06cd1f..d6adfa0`）、計画レビューの後に `implementation-plan.md` を直した commit、台帳 2 本、PR #49〜#53 の本文と CI の記録である。取りまとめ役がレビュアーと実装者を動かしたときに見たこと（レビュアーの報告の届き方、作業ツリーの使い方、伝言の届き方）は、リポジトリに残らないので、ここに書いた。

## M33 をこのサイクルに入れなかったこと

`guides/dev-cycle.md`「全体の流れ」の表は、サイクル 04 に M33（フロントエンド）を入れていた。M33 は計画レビューを Go で通したが、着手の前に作者に確かめる著者判断（OI-07〜OI-14）と公開の時期（OI-06）が `blocked-user` のまま残り、着手できない。M33 を待つと、M37・M30〜M32 で分かったことが正本へ戻らないまま止まるので、取りまとめ役は M33 をサイクル 05 へ移し、サイクル 04 を 4 つのマイルストーンで閉じた。移し方の規則は、再発防止で `guides/dev-cycle.md`「全体の流れ」と `guides/cycle-end.md`「開始の確認」に書いた（`recurrence.md`）。

## 回し方の改善の提案

`guides/dev-cycle.md` か `guides/cycle-end.md` への変更として書く。機械で止められるものは、再発防止（段階 4）で検査や補助の形を直すので、ここでは提案だけを書く。

1. **作業ツリーに書き込む担当を並べるときは、担当ごとに worktree を分ける**（`dev-cycle.md`「着手の前に」）。実装者に限らず、計画レビューの直し・台帳の直し・サイクル末の担当にも当てる
2. **Claude のレビュアーの結果は、依頼に書いたファイルを正の受け取り口にする**（`dev-cycle.md`「独立したレビュアー」）。最終報告は届かないことがあり、届いたときも、ファイルと同じ内容であることを確かめてから使う
3. **作業中の担当に作者の判断を渡すときは、先に台帳の行に書き、担当に行の ID を読み直させ、読んだことの返事を待つ**（`dev-cycle.md`「作者が不在の間に決めたこと」の周辺）。PR を出す前に、引当先がそのマイルストーンの行を読み直す
4. **手順には、その実行にだけ効く形のコマンドを書く**（`dev-cycle.md`「文書の置き場と、書く前の振り分け」）。ホストの全体の設定を変えるコマンド（アカウントの切り替え・全体の git の設定・インストール）を書かない
5. **Codex の一時の失敗は、同じ依頼で 1 回出し直し、それでも失敗したら Claude の系統だけで判定する**（`dev-cycle.md`「独立したレビュアー」）
6. **作者の判断を待って着手できないマイルストーンは、次のサイクルへ移してサイクル末に入る**（`dev-cycle.md`「全体の流れ」、`cycle-end.md`「開始の確認」）。移したマイルストーンは、次のサイクルの計画レビューに含め直す
