# サイクル 01 の振り返り

サイクル 01（M15〜M20）の計画が実装にどれだけ合っていたかと、回し方そのものが働いたかを評価した記録である。手順は `guides/cycle-end.md`「1. 振り返り」にある。ここで挙げた想定外は、知見の収穫（`harvest.md`）と再発防止（`recurrence.md`）の入力になる。

読んだものは、計画レビューの証跡（`plan-review.md`）、実装レビューの証跡（`implementation-reviews.md`）、レビューの原文、サイクルの commit の履歴（`e72af36..cycle-01-end`）、計画レビューの後に `implementation-plan.md` を直した commit、台帳 2 本である。

設計文書・ADR・計画が各マイルストーンに割り当てた制約は、次のとおり完了条件と実装に落ちている。エラー通知にテナント ID を付ける（`decisions.md` 2 章、M18）、付帯情報を直列化の項目に持つ（`adr/005` 決定 3、M18）、監査の対象の定義と mutation ごとの表（M19）、「ページングと N+1」の 2 つの規則（M17）、例外の一覧を空に保つ（M17 の Bullet の許可リスト、M20 の `breaking-changes.yml`）。

## 想定外

想定外はどれも回し方かテストの基盤の扱いに関わり、設計と実装のやり方の候補ではないので、改善の候補の台帳には移さず、再発防止（段階 4）に渡す。

| 想定外 | 原因 |
|---|---|
| 台帳の OI の番号がぶつかった。M18 の実装レビューの直しで足した OI-35・OI-36 と、並行で進めた M19 の OI-35〜OI-42 が同じ番号になり、M19 の行を振り直した | 台帳の採番は「最後の番号の次」で、1 本の流れを前提にしている。積み重ねたブランチの上下を並行で書くと、それぞれのブランチの中では番号が続くので、`bin/check-open-items` はどちらのブランチでも通り、重なりは載せ直しの衝突で初めて見える |

## 回し方の改善の提案

`guides/dev-cycle.md` か本書への変更として書く。機械で止められるものは、再発防止（段階 4）で検査を足すので、ここでは提案だけを書く。

1. **レビュアーへの依頼の型を決める**（`dev-cycle.md`「独立したレビュアー」）。取りまとめ役は、段階ごとの 5 つの観点・判定の定義・違和感の欄を依頼にそのまま入れ、レビュアーの全体の判定を定義（Critical と High の有無）に照らして証跡に写す。マイルストーンに固有の確かめどころは、5 つの観点の下に足す
2. **読み直しの範囲と打ち切りを決める**（`dev-cycle.md`「判定の形」）。読み直しでは、前の指摘の解消と、High 以上の新しい指摘だけを判定に使う。読み直しで出た Medium 以下は、そのマイルストーンで直すか台帳に積み、もう一度の読み直しには出さない
3. **テストの基盤のガードを必ず付ける**（`dev-cycle.md`「テストから書く」と、実装レビューの観点 4）。除外・包み・後始末・補助のような基盤を足すときは、その防壁を外すと落ちる example を足す。実装レビューは、基盤の防壁を外したときに何が落ちるかを必ず見る
4. **spec を移すときは `expect` を対応づける**（`guides/testing.md`「層への配分」に置く手順）。消す example の `expect` を 1 つずつ移し先に対応づけた表を証跡に残し、対応先の無い `expect` は消さない
5. **証跡の数値に、流したコマンドと commit を添える**（本書の各段階の「出すもの」と `dev-cycle.md`「テストから書く」）
6. **積み重ねの下の段の直しの扱いを決める**（`dev-cycle.md`「ブランチと PR」）。`handoff.md` の件数のように毎回変わる行は、積み重ねの最上段だけが書き換える。下の段に直しを入れたら、上の段を載せ直し、台帳と証跡の SHA を置き換える
7. **台帳と証跡の SHA が HEAD の祖先であることを機械で確かめる**（段階 4 で `bin/check-open-items` に足す）。CI の `actions/checkout` は既定で履歴を 1 commit しか取らないので、この検査を流すジョブは履歴を全部取る（`fetch-depth: 0`）か、検査の前に履歴を深くする。履歴が足りないときに「祖先でない」と誤って落とさない
8. **台帳の採番を並行のブランチで重ねない**（`dev-cycle.md`「残件の台帳」）。番号の重なりは、`bin/check-open-items` がすでに各ブランチで検出するが、並行のブランチは互いを見ない。台帳に行を足すのは、積み重ねの最上段で、下の段を取り込んだ後に限る
9. **実装中に設計文書を直したら、計画の節も直す**（`dev-cycle.md`「実装レビュー」の観点 5）。直した記述と同じものが計画の節にあれば、計画の節を設計文書への参照に置き換える
10. **指摘を直すときは、直す前の形を種類で数える**（`dev-cycle.md`「実装レビュー」）。指摘の文言だけでなく、同じ種類の前の形を `git grep` で数え、0 件にしてから閉じる
11. **並行で動く実装者を worktree で分ける**（`dev-cycle.md`「2. マイルストーンの実装」）。取りまとめ役は、並行で動かす実装者への依頼に、作業の場所（worktree）と一時ファイルの置き場を書く

## 証跡の置き場をそろえた

`guides/dev-cycle.md` と本書は、証跡を `plans/cycle-NN/` の下に段階ごとの名前で置くとしている。計画レビューと実装レビューの証跡だけが `plans/cycle-01-plan-review.md`・`plans/cycle-01-task-reviews.md` にあったので、手順書の形にそろえ、`plans/cycle-01/plan-review.md`・`plans/cycle-01/implementation-reviews.md` へ移した。サイクル末の 5 つの証跡が同じ場所に並び、次のサイクルからは手順書の名前どおりに作ればよい。参照は、実装レビューの証跡の中の自分の名前（SHA の置き換えの節）だけで、ほかの追跡しているファイルからの参照は無かった。証跡は後から書き換えないが、この名前の直しと、M15 の節に紛れていた M16 の読み直しの段落を M16 の節へ移すことは、記録の中身を変えないので行った（OI-51）。マージ済みの PR #22 の本文は古い名前を指すが、PR の本文は書き換えない。
