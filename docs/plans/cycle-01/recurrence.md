# サイクル 01 の再発防止

サイクル 01（M15〜M20）で直し終えた指摘と食い違いの原因をたどり、同じ種類が再び起きない仕組みを足した記録である。手順は `guides/cycle-end.md`「4. 再発防止」にある。直すこと（是正）は各マイルストーンと逸脱検査で済んでいるので、ここでは予防だけを扱う。知見の収穫（`harvest.md`）に書いた知見は、ここに書かない。

読んだものは、実装レビューの指摘（Critical・High・Medium と、振り返りで 2 回以上と数えた種類の Low）、逸脱検査で「文書が正」と裁定した D1・D5・D6、振り返りの想定外である。指摘は、振り返りの「指摘の数」の種類ごとにまとめ、まとめた行に指摘の出どころをすべて挙げた。

## 指摘ごとの種類・原因・修正先

種類は、範囲の逸脱 → 生成物のずれ → 規則の違反 → 文書との食い違い → 暗黙の知識、の順に当てて最初に当たったものにした。「捕まえるべきだった段階」は、計画レビュー・実装・実装レビューのどれかである。

| 指摘（出どころ） | 種類 | なぜ起きたか | なぜ防げなかったか | 捕まえるべきだった段階 | 修正先と分類 | 再び起きたら捕まる段階 |

| 実装やテストの基盤を壊しても、テストが落ちない（M15 Cop の spec、M16 X3・X4・X5、M17 X1・X3・C3・X4、M18 Y2、M19 C2） | 暗黙の知識 | 実装者は、自分で選んだ壊し方だけで確かめる。除外・包み・後始末・補助のようなテストの基盤は、業務の実装ではないので壊す対象に挙がらなかった | 「テストから書く」は実装を壊すことだけを求め、基盤を名指ししていなかった。実装レビューの観点 4 も同じ | 実装 | `dev-cycle.md`「テストから書く」に、基盤を足したらガードの example を足すことを書き、観点 4 に基盤を外したときに何が落ちるかを必ず見る項目を足した（手順） | 実装レビュー（観点 4 の必ず見る項目） |
| 証跡・台帳・PR の本文の記録の誤り：数値が再現しない（M16 C11、M18 C6、M20 X3・C5）、残件を片付けずに閉じた（M16 C1）、PR の本文の書き漏らし（M15、M16 C9） | 暗黙の知識 | 数を書いた後に直しの commit が入り、どの時点の数かが書かれていなかった。`closed` は「片付けた」で、判断で決めたものは `judgment` という区別を、実装者が取り違えた | 証跡に数を書く形の規則が無かった。状態の区別は `dev-cycle.md` の表にあるが、実装者への依頼で示していなかった | 実装 | `dev-cycle.md`「テストから書く」に、件数と再現率に流したコマンドと commit を添えることを書いた（手順） | 実装レビュー（観点 1：結果が diff と実行結果に一致するか） |

| 文書の記述が実装・事実と食い違う（M15 導出しない理由、M16 X6・C10、M18 X4・C5、M19 X1） | 文書との食い違い | 実装の後に文書を書くとき、実装と照らし直さなかった。まだ無い仕組みを事実として書いた（M16 C10） | 実装レビューの観点 5 が見る項目で、実装レビューで捕まえた。仕組みは働いた | 実装レビュー | 何も足さない。6 件とも実装レビューで捕まった。機械で判定できる部分（節の参照）は下の行で検査にした | 実装レビュー（観点 5） |

## 振り返りの想定外のうち、回し方の手順に足したもの

指摘ではないが、回し方が働かなかった想定外である。どれも `guides/dev-cycle.md` に足した（手順）。

| 想定外 | 足したもの | 再び起きたら捕まる段階 |
|---|---|---|
| 観点ごとの判定と違和感が、どのレビューでも出なかった | 「独立したレビュアー」に「依頼の型」を足した（対象・5 つの観点・判定の定義・出す形） | サイクル末の振り返り（成果物の有無を確かめる） |
| Codex の判定が、読み直しのたびに新しい Medium を出して終わらなかった | 「判定の形」に、重大度から判定を決め直すことと、読み直しは High 以上だけで判定することを足した | 実装レビュー |
| 台帳の番号が、並行のブランチでぶつかった | 「ブランチと PR」に、台帳に行を足すのは積み重ねの最上段に限ることを足した。番号の重なりと飛びは、いまも `bin/check-open-items` が各ブランチで落とす | CI（載せ直した後の `bin/check-open-items`） |
| 下の段の直しで、上の段が `handoff.md` の件数の行で衝突した | 同じ節に、毎回変わる行は最上段だけが書き換えることを足した | 載せ直し |
| 実装者がメインの作業ツリーに一時ファイルを作った | 「着手の前に」に、並行の実装者の依頼に worktree と一時ファイルの置き場を書くことを足した | 取りまとめ役の依頼 |

## 機械にした検査と、壊して落ちることの確かめ

| 検査 | 壊し方 | 落ちたもの |
|---|---|---|
| `bin/check-commit-refs`（`spec/bin/check_commit_refs_spec.rb`） | 浅い clone の判定を外す | `履歴が浅い clone では、確かめずに失敗する` |
| 同上 | 祖先の確かめを外す | `どのブランチにも無い SHA と、HEAD の祖先でない commit の SHA を落とす` |
| 同上 | commit の有無の確かめを外す | 同じ 1 件 |
| `spec/rubocop/section_references_spec.rb` | `db/migrate/20261008000800_create_fulfillment.rb` の参照を「出荷」に戻す | `リポジトリの参照は、すべて実在の見出しを指す` |
| 同上 | `graphql-schema.md` の参照を「購買」に戻す（ファイル名をバッククォートで囲む形） | 同じ 1 件 |
| 同上 | ファイル名をバッククォートで囲む形を拾わない | 拾い方の見本の example |
| 同上 | 見出しの「：」の前後で指す参照を許さない | 2 件とも |
| 同上 | コードブロックの中も拾う | 2 件とも |
| `spec/rubocop/bin_scripts_spec.rb` | `bin/check-open-items` のコメントを `--due M16` に戻す | `経緯・マイルストーンの番号・予定を書かない` |
| `bin/check-open-items` の番号の検査（既存） | 番号の連続の確かめを外す | `番号の飛びと重複を落とす` |

壊したファイルは複製から戻し、`git diff` で意図した変更だけが残ることを確かめた。
