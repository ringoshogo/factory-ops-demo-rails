# サイクル 08 の終わりに作者が決めること

サイクル 08 のサイクル末の PR をマージする作者が、判断の要る点を 1 件ずつ決めるために読む。各項目は、何が問題か、流用元（`factory-ops-demo`）ではどうしているか、選べる形ごとの作るものと作業量と見せ場、いまの形（既定）と取りまとめ役のおすすめ、を書いた。流用元の作りは、取りまとめ役が流用元の実物（`frontend/app/layout.tsx`・`frontend/e2e/live/helpers.ts`・`frontend/playwright.config.ts`・`backend/internal/testsupport/db.go`・`backend/main_test.go`）を読んで確かめた。作業量は、`b15b213` のコードと改善の探索の調査（`improvement.md`）で確かめた。決まった答えは、取りまとめ役が台帳（`open-items.md`）の行の結果の欄に書き、行の ID で担当に渡す（`guides/dev-cycle.md`「残件の台帳」）。

答え方：項目ごとに「既定のまま」か、選ぶ形の記号を書く。全部既定でよければ「全部既定で」。おすすめが既定と違う項目（1）は、おすすめの形を書くか「既定のまま」を書く。

## 読む順

おすすめが既定と違う問い（1）を先に、作者が手を動かすこと（2・3）を次に、確かめるだけの判断（4〜7）を最後に置いた。サイクル 08 には、答えで作るものが変わる問いは無い。

## 1. 作者の手元に残る、前の担当の一時の DB 13 個を消すか

- **何が問題か**：rspec と E2E を担当ごとに別の DB で流すと、一時の DB（`factory_ops_m47_test` など）が残る。サイクル 08 の M51 で、一時の DB を一覧して名前を明示したときだけ消すタスク（`RAILS_ENV=test bin/rails temp_databases:list`・`"temp_databases:drop[<名前>]"`）を足し、M50 の残りと M33 の残りの担当は自分の DB を消して終えた。M51 より前の担当とレビュアーが作った 13 個（M30 のレビュー・M33・M45・M47・M49・M50 の分。どれも接続 0）は、誰の作業にもならず残っている（`retrospective.md` の想定外 7）。残った DB は、PostgreSQL のイメージを上げて照合順序の版を改めるときに、作り直す手間を残った数だけ増やす（`guides/config.md`「照合順序の版」）。M51 の担当の 2 個は、取りまとめ役が担当を止めるときに消す
- **流用元では**：Go のテストが作業用の DB を作り、`t.Cleanup` でテストの終わりに必ず消す（`backend/main_test.go` の `createFreshDB`）。ほかのテストは共有の DB を各テストの冒頭で空にする（`backend/internal/testsupport/db.go` の `Truncate`）。担当ごとの一時の DB が残ることは無い
- **選べる形**

  | 形 | 作るもの | 作業量 | 見せ場 |
  |---|---|---|---|
  | 既定 | 無し。作者が必要なときに手で消す | 作者の手で 13 回のタスクか `dropdb` | 無し |
  | (a) 取りまとめ役が 13 個を消す | 無し。取りまとめ役が `temp_databases:list` で接続 0 を確かめてから、名前ごとに `temp_databases:drop` を流し、結果を台帳に書く | 小さい（13 回のタスク。`FORCE` なしなので、接続のある DB は消えずに失敗する） | 無し |

- **既定**：作者が手で消す
- **おすすめ**：(a)。M51 のタスクは、名前の規則と既定の 3 つの DB を拒む形で、作者の開発と本番の DB に触れない
- **答えで変わること**：(a) なら、取りまとめ役がサイクル 09 の初めに消し、IB-130 の判定（サイクル 09 の末）の範囲から 13 個を外したことを台帳に書く

## 2. 公開の配置の実機の手順（OI-196、M41 の残り）

- **何をするか**：`deploy/README.md`「作者の手順」1〜6 を Raspberry Pi で流し、測ったメモリ、5 万行の取り込みの間の Pod の再起動の回数（`RESTARTS`）、公開の URL で確かめたこと、流用元のデモが動き続けることを、PR か台帳の OI-196 に書く。結果が書かれるまで M41 は閉じず、公開しない
- **このサイクルで変わったこと**：M50 の残りで品目の単位の列も `ja-x-icu` にした。公開の配置は毎日 DB ごと作り直すので、作り直しの後は気にしなくてよい。M51 で `publish` の `if:` に `success()` を明示したが、GHCR にイメージを置く条件は変わっていない
- **あわせて決めてほしいこと**：M41 の残りを次のサイクルへ移すのは、サイクル 06・07・08 に続いて 4 回目である（IB-133）。既定は、結果が来るまで毎サイクル移し続ける形で、費用は無い。(a) サイクルの表から M41 の残りを外し、作者が結果を書いたときに取りまとめ役が次のサイクルに入れる形にもできる（`dev-cycle.md` のサイクルの表の 1 行と、計画の M41 の節の 1 文）。どちらでも、`bin/check-open-items --due M41` は OI-196 で落ち続け、公開しないことは変わらない。おすすめは既定のまま（台帳とサイクルの表から待っていることが見え続ける）

## 3. M33 の画面の細かい指摘（OI-177）

作者が画面を動かした後に出すとした指摘で、台帳では `open` のまま待っている。出したら、取りまとめ役が指摘ごとに台帳に写し、画面だけで済むか API に及ぶかを書いて、M33 の残り（サイクル 09）で直す。サイクル 08 で、取り消した伝票の詳細の明細の行に「品番未照合（取消）」「未確定（取消）」と出すようにした（OI-204。下の 7）。品目の単位は流用元と同じ「個 < 箱 < 本」の順に並ぶ（OI-199）

## 4〜7. 確かめるだけの判断

取りまとめ役か担当が、作者に確かめられないまま決めたことである。どれも既定で作ってあり、違う形を求めるときだけ答える。内容と理由は台帳の各行にある。

### 4. テストの around が送出したときも、example のトランザクションを巻き戻す補助を全 spec に効かせる（OI-205）

- **何が問題か**：rspec は example ごとにトランザクションを開いて、終わりに巻き戻す。example を包む around（たとえば `Tenancy.with_tenant { example.run }`）が、SQL のエラーの後に例外を送り出すと、rspec-rails の巻き戻しが飛び、トランザクションとロックが接続に残って、同じファイルの後ろのグループが止まっていた（IB-123。M51 の調べで分かった）。取りまとめ役の判断（D-1）で、`spec/support/around_hook_errors.rb` を `spec/rails_helper.rb` で全 spec に効かせ、around の送出を example の失敗に移して巻き戻すようにした。本番の `Tenancy` は変えていない。around が送出したときの rspec の出力は、送出が example の失敗として出る形に変わる
- **流用元では**：Go のテストは example ごとのトランザクションを使わず、各テストの冒頭で共有の DB を空にする（`backend/internal/testsupport/db.go` の `Truncate`）ので、落ちたテストがトランザクションを残す形が無い
- **選べる形**：既定。(a) 補助を外し、落ちた example を包む around だけを個別に直す（小さいが、同じ形の around を足すたびに同じ止まりが戻る）。(b) 流用元と同じく、example ごとのトランザクションをやめてデータを消す形にする（大きい。行列の世界をファイルごとに 1 回作る形（M36）と RLS を開く共有の文脈を作り直す）
- **見せ場**：既定は、1 つの example の失敗が後ろのテストを止めない守りとして見せどころのテーマ 9 に載せた。(a)(b) は見せ場にならない
- **おすすめ**：既定のまま

### 5. E2E のログインの後の URL の期待にだけ 20 秒の待ちを渡す（OI-206）

- **何が問題か**：手元の E2E が、ログインのボタンを押してから移った先の URL になるまでを Playwright の既定の 5 秒で待ち、マシンが混むと落ちていた（IB-117）。M51 で、手元の E2E の Rails も起動の時に読み込むようにし、ログインの URL の期待にだけ 20 秒を渡した。値は、負荷のある手元でボタンを押してから時間切れまでが 15.5 秒に達した回と、サイクル 07 の記録（10 秒と 17 秒）から決めた。ほかの期待は 5 秒のまま
- **流用元では**：ログインが無く、デモを開始するボタンの後に `page.waitForURL(/\/dashboard$/)` で待つ（`frontend/e2e/live/helpers.ts` の `startDemo`）。時間の指定が無く、Playwright の既定ではテスト全体の時間切れ（既定 30 秒）まで待つ
- **選べる形**：既定。(a) 流用元と同じく値を指定せず、テスト全体の時間切れ（このリポジトリは 60 秒）まで待つ（`world.ts` の 1 行。小さい）。(b) 5 秒に戻す（1 行。手元が混むと落ちる）
- **見せ場**：どの形も無い
- **おすすめ**：既定のまま。ログインが済んだかだけを確かめる待ちで、上限を明示したほうが、遅くなったときに落ちる場所と理由が読める

### 6. 画面の書体を、直りを含む Next の版が来るまで `next/font/google` のまま置く（IB-101）

- **何が問題か**：CI の画面の組み立てが、まれに `next/font/google queries have exactly one entry` で落ち、失敗したジョブを流し直すと通る（M42・M47・M33 の残りで 3 回、174 回の実行のうち）。サイクル 08 の改善の探索で、原因が、Google Fonts が時々返す拡張子の無い書体の URL を Next 16.4 が解析できない不具合だと分かった（Next の issue #99114）。上流では直り（PR #100158、`16.5.0-canary.13`）、安定版の 16.4.1 には入っていない。改善の探索の裁定は、直りを含む安定版を Dependabot が運ぶのを待つ形にした（`improvement.md`「裁定」）
- **流用元では**：同じく `next/font/google` で `IBM_Plex_Sans` を読み、英数字だけを自前で配る（`frontend/app/layout.tsx`）
- **選べる形**：既定（待つ。同じ文言なら失敗したジョブを 1 回流し直し、証跡に書く）。(a) `next/font/local` に移し、書体のファイル（latin の 3 つの太さで約 71 KB）と許諾の文（SIL Open Font License の `OFL.txt`）を置く（小さい。`layout.tsx` の約 10 行、CSP と Docker の組み立ては変えない。字形と太さは見比べが要る）
- **見せ場**：既定は、原因を観測で確かめて待つ判断として改善の探索に残る。(a) は組み立てが外部に頼らない形になるが、流用元と書体の取り方が分かれる
- **おすすめ**：既定のまま。直りを含む版の後も落ちるか、流し直しで通らない回が出たら (a) に移す（台帳の調べ直す条件）

### 7. 取り消した伝票の明細の行の文言（OI-204）

- **何が問題か**：作者は OI-204 で、照合待ち・確定待ちのまま取り消した伝票の明細の行も取消に合わせ、文言は実装で決めると答えた。M33 の残り（サイクル 08）で、受注は「品番未照合（取消）」、発注は「未確定（取消）」にした（計画の既定のまま）。取り消した受注の文言は注意の色にせず、控えめの色にした
- **流用元では**：無い。品番照合が無く、すべての明細が品目を持つ
- **選べる形**：既定。違う文言を求めるなら、`frontend/lib/format.ts` の 1 か所と単体と E2E の期待を替える（小さい）
- **見せ場**：無い
- **おすすめ**：既定のまま
