# サイクル 08 の計画レビュー：M51 と、M50・M33・M41 の残り

この文書は、`implementation-plan.md` の M51 と、M50・M33・M41 の「残り（サイクル 08）」を 2 系統の独立したレビュー（Claude と Codex）にかけ、指摘を計画に反映した記録である。M51 から着手する担当者と、計画をレビューする人が読む。担当者は、計画の節が「なぜこう書いてあるか」をここで引ける。

サイクル 08 に入るのは、サイクル 07 の改善の探索で起こした M51 と、サイクル 07 から移した M50・M33・M41 の残りである。作者は 2026-10-15 に、サイクル 07 の終わりの問い（`plans/cycle-07/author-decisions.md`）に答えた。取りまとめ役は、レビューに出す前に、答えを節に書いた（`6ce4be0`）。OI-203（`publish` の `if:` に `success()` を明示する）は M51 の作るもの 7 に、OI-199 の (a)（品目の単位の列も `ja-x-icu`）は M50 の残りに、OI-204 の (a)（取消済の伝票の明細の行も取消に合わせる）は M33 の残りに書いた。M41 の残りは、作者の実機の手順の結果（OI-196）を待つだけで、作るものは変わらない。

初回のレビューは `6ce4be0` を読んだ。依頼には読む版の commit を書き、その版を展開したディレクトリだけを読ませた。Claude は Go、Codex は Conditional Go で、High は Codex の 1 件だった。High を直した版（`55459b3`）に初回の記録を足した版（`c26dc4a`。計画の節と台帳は `55459b3` と同じ）を、2 系統で読み直した（読み直し 1）。2 系統とも、初回の High と Medium の解消を認め、新しい High 以上は無く、Go だった。M51 から着手できる。読み直し 1 の結果は末尾の「読み直し 1」にある。Claude のサブエージェントは、2 回とも最終報告を返さずに終わり、依頼に書かせた結果のファイルから読んだ（`guides/dev-cycle.md`「独立したレビュアー」）。Codex は、2 回とも展開したディレクトリが git のリポジトリでないので `--skip-git-repo-check` を付けて流し、一時の失敗は起こさなかった。

読む順は、マイルストーンの分け方 → マイルストーンごとの判定 → 指摘ごとの対応 → 作者に渡すもの → 直さなかった指摘と台帳に積んだもの、である。指摘の出典は次の形で示す。2 系統の ID がぶつかるときは、`Codex M51-1` のように系統を添える。

## マイルストーンの分け方

| マイルストーン | 中身 | 分けた理由 |
|---|---|---|
| M51 手元の検証を止めるものを取り除く | E2E の Rails の読み込みとログインの待ち（IB-117）、一時の DB の一覧と削除（IB-130）、ポリシーの足し外しの待ちの上限（IB-123）、`thenBy` の空の配列（OI-202）、`publish` の `success()` の明示（OI-203） | サイクル 07 の改善の探索で起こした。OI-203 は CI の 1 行と spec と文書の直しで、別のマイルストーンを起こすほどの大きさが無く、M48 と同じブランチへの push の確かめを伴うので、テストの基盤と道具を直す M51 に足した |
| M50 の残り | `items.unit` を `ja-x-icu` にするマイグレーション、`collations_spec.rb`、「個 < 箱 < 本」の request spec、E2E、`data-model.md`（OI-199） | サイクル 07 で移した。作者の答えで、値の差し替えの形が決まった |
| M33 の残り | 取消済の伝票の詳細の明細の行の文言（OI-204）、作者の画面の指摘を待つ OI-177 | サイクル 07 で移した。OI-204 は OI-177 の答えが無くても作れる |
| M41 の残り | 作者の実機の手順（OI-196） | 作者を待つだけで、取りまとめ役が作るものは無い |

実装の順は M51 → M50 の残り → M33 の残りで、M41 の残りは作者の結果が書かれたときに片付ける。M51 を先に置くのは、改善の探索で採用した変更をサイクルの最初に置く規則（`guides/dev-cycle.md`「全体の流れ」）による。M51 が手元の E2E のログインの待ちをそろえるので、後の 2 つの E2E は、その上で手元で全体を通せる。M50 の残りは M51 と同じ `spec/requests/catalog_spec.rb` を、M33 の残りは M50 の残りと同じ `frontend/e2e/list-pagination.spec.ts` を直すので、この順に積む（前提の表の M50・M33 の行）。

サイクル 08 は 4 つで、1 つのサイクルの上限に収まる。M41 の残りは作者を待つだけで、M33 の残りの OI-177 も作者の指摘を待つ。待ちの行が片付くまで、そのマイルストーンを終えたと記録しない。

- `remove!` の待ちの上限と、ポリシーが残ったときの後片付けを確かめる example が無く、`add!` の側だけを確かめても完了と判定できる（Claude M51-2・Codex M51-2。どちらも Medium）
