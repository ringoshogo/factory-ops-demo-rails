## 調べたテーマ

### 1. IB-101 画面の組み立ての時の `next/font/google` の失敗

台帳の見送りの理由（取得の失敗か Turbopack の内部の失敗かを切り分けていない）と、調べ直す条件（失敗の前段の通信のログか、キャッシュの無い状態で通信を断った比べ）との差分だけを調べた。

- **いまの形**：`frontend/app/layout.tsx` が `IBM_Plex_Sans` を `next/font/google` から読み、太さ 400・500・600、`subsets: ["latin"]`、`display: "swap"` を指定する。Next は 16.4.0。CSP は `frontend/security-headers.json` の `font-src 'self'` で、`next/font` は書体を組み立ての時に取って自前で配る
- **原因**（Claude。手元で再現した）：落ち方は通信の失敗でも Turbopack の一般の内部の失敗でもなく、Google Fonts が時々返す拡張子の無い書体の URL（`https://fonts.gstatic.com/l/font?kit=…&skey=…`）を、Next 16.4.0 が解析できないことだった。文言 `next/font/google queries have exactly one entry` は、書体のファイルを取りに行く前に、CSS に埋めた値をクエリ文字列として読む段で、URL の `&` で項目が割れて出る。Next の issue #99114（https://github.com/vercel/next.js/issues/99114 ）が同じ文言と原因を報告し、PR #100158（https://github.com/vercel/next.js/pull/100158 、2026-10-15 にマージ）で直り、`16.5.0-canary.13` に入った。いまの最新の安定版 16.4.1 には入っていない。これまでの 3 回（M42 の `e2e`、M47 の `images`、M33 の残りの `e2e`）のログは、どれもこの文言を含む。2026-10-12 以降の 174 回の実行で 3 回、組み立ての回数でおよそ 1% である
- **手元での確かめ**（Claude。macOS の `sandbox-exec` で外への通信を断ち、終わった後に写したものを消した）

  | 条件 | 結果 |
  |---|---|
  | 通信を断ち、キャッシュなし | `Failed to fetch IBM Plex Sans from Google Fonts` で落ちた。CI と違う文言 |
  | 通信を断ち、モックで拡張子のある `.woff2` の URL を返す（書体のファイルの取得だけが失敗する形） | 取得の警告と `Can't resolve …/font/google/font`。`queries have exactly one entry` は出ない |
  | 通信を断ち、モックで拡張子の無い `/l/font?kit=…` の URL を返す | CI と同じ 2 つの文言で、毎回落ちる |
  | 上と同じモックで、Next を `16.5.0-canary.13` に替える | 文言は出ず、書体のファイルを取りに行って断った通信で落ちるだけになった |

  サイクル 07 の調査が推した「通信を断った `next build` を RED にする」形は、CI と別の文言で落ちるので、CI の落ち方を再現しない。Codex は、展開したディレクトリに依存が無く書き込みもできないので再現できず、原因を分ける証拠は増えていないとした
- **比べた形**：(a) `next/font/local` に移し、書体のファイルを置く（https://nextjs.org/docs/app/getting-started/fonts 「Local fonts」）。(b) npm の包み（`@fontsource/ibm-plex-sans`、OFL-1.1）を依存に足して指す。(c) 直りを含む Next の安定版を待つ。`package.json` は `^16.4.0` で、Dependabot の毎週のまとまりが運ぶ。(d) いまのまま、同じ文言なら失敗したジョブを 1 回流し直す
- **合い方**：原因が Google の応答の形と Next の不具合と分かったので、(c) は費用 0 で原因そのものを消すが、安定版の時期は確かめていない。(a)(b) は組み立てを外部から切り離し、Google の応答の別の変化にも当たらない。issue #99114 のコメントは、同じ書体で 20 分に 5 回続けて落ちた例を挙げており、(d) の流し直しで通らない時間帯がありうる。IB-113 で `images` も PR のたびに組み立てるので、当たる回数は M47 より前の 2 倍になった
- **移す費用**（(a)。2 系統がファイルを読んで確かめた）：latin の 3 つの太さで 3 ファイル、計約 71 KB（Claude が `@fontsource/ibm-plex-sans` 5.3.0 で測った。Codex は未測定）。IBM Plex は SIL Open Font License 1.1 で、配るときは著作権の表示と許諾の文（`OFL.txt`）を添える。`layout.tsx` は約 10 行の差し替えとコメントの直しで、`globals.css` の `var(--font-plex-sans)` は変わらない。CSP は変えない。`frontend/Dockerfile` は `frontend/` を丸ごと写すので変更は要らない。見た目の差は画面の寸法の E2E が捕まえる。いまの `next/font/google` は 6 つの subset の `@font-face` を出すが、画面の文字は和文（OS の書体）と ASCII なので latin だけで足りる見込み
- **効いたとする基準**：(a) なら、`next/font/google` の参照が 0 件で、通信を断った手元でキャッシュの無い `next build` と Docker の組み立てが通り、画面の寸法の E2E が通る。(c) なら、16.5.0 以降を入れた後に、拡張子の無い URL のモックで `next build` がこの文言で落ちない
- **推奨**：2 系統とも `見送り` のまま。理由は割れた。Claude は、見送りの理由だった切り分けは解け、原因は上流で直ったので、次の安定版を待つとし、台帳の行の「取得の失敗」を前提にした書き方を原因に合わせて書き換え、調べ直す条件を (1) 安定版が直りを含まないまま CI で同じ文言がもう 2 回出たとき、(2) 16.5.0 以降で Google Fonts に由来する失敗が 1 回でも出たとき、(3) 書体を替えるとき（どれも (a) に移す）とした。外部への依存を消すこと自体に価値を置くなら、(a) は 1 つのマイルストーンに入る大きさだとも書いた。Codex は、再現できず原因を分ける証拠が無いとして、前回の条件のまま見送りとした
