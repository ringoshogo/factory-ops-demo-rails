# サイクル 08 の逸脱検査

サイクル 08（M51・M50 の残り・M33 の残り）の成果物が正本から外れていないかを、2 系統のレビュアーが検査した記録である。手順は `guides/cycle-end.md`「3. 逸脱検査」にある。ここで「文書が正」と裁定した食い違いは、再発防止（`recurrence.md`）の入力になる。

レビュアーに渡したのは、サイクルの diff（`9ae7462..8c8bb1f`。`8c8bb1f` は振り返りと知見の収穫の commit）、正本（知見の収穫で足したものを含む）、サイクルのマイルストーンの節、振り返りの「計画から実装への逆向きの照合」、実装レビューの証跡、台帳である。依頼には読む版を `8c8bb1f` と書き、その版を展開したディレクトリだけを読ませ、このサイクルに固有の確かめどころ（取消の明細の文言と色、`items.unit` の照合順序、テストの DB にだけ足すポリシーの打ち切りと権限、空の `thenBy`、ADR 009 の `publish` の条件、一時の DB と E2E の読み込みの規約）を観点の下に足した（`guides/dev-cycle.md`「依頼の型」）。どちらもテストは流さず、ファイルと行を照らした。Claude のサブエージェントは最終報告を返さずに終わり、依頼に書かせたファイルから結果を読んだ。Codex は `--skip-git-repo-check` を付けて流し、一時の失敗を起こさなかった。

## 違和感

- **`handoff.md` の「次にやること」が M51 の計画レビューから始めると書き、同じ文書の「開発環境」と食い違う**（Claude）→ 台帳の棚卸しで直した（`inventory.md`）
- **`publish` の `if:` の spec は、`success()` を含み 3 つの関数を含まないことだけを照らし、守りを外す式も通る**（2 系統）→ IB-134 にある。改善の探索に送った（`improvement.md`）
- **`around_hook_errors.rb` は全 spec に効くが、`testing.md` の行列の節の中にしか書かれていない**（Claude）→ 行列のほかの spec を書く人が読む場所が無い。判断の確認は OI-205 で作者に渡し、置き場は IB-138 に積んだ
- **`config.md` の一時の DB の段落の「作る入口だけで」が、消すタスクを足した後には作る入口しか無いように読める**（Claude）→ 「作る入口が作り」に直した
- **spec の `stop_waiting_owner` は、DB で Lock を待つ所有ロールの接続をすべて終わらせる**（Claude）→ 1 つのテストの DB を 2 つの実行で使わない規則（`testing.md`）が前提で、規則どおりなら害は無い。扱うことは無い
- **`format.ts` の冒頭の説明と `TotalStatus` の名前が用途とずれる**（Codex）→ IB-137 にある
- **振り返りが挙げた `judgment` の欠けと M50 の残りの CI の結果は、検査の版では解消している**（Codex）→ OI-205・OI-206 は知見の収穫の commit で登録し、CI の結果は M33 の残りの担当が書いた。食い違いには数えない
