# サイクル 03 の逸脱検査

サイクル 03（M36・M25・M26・M28・M27・M29）の成果物が正本から外れていないかを、2 系統のレビュアーが検査した記録である。手順は `guides/cycle-end.md`「3. 逸脱検査」にある。ここで「文書が正」と裁定した食い違いは、再発防止（`recurrence.md`）の入力になる。

レビュアーに渡したのは、サイクルの diff（`201290a..be5b3c7`。`be5b3c7` は知見の収穫の commit）、正本（知見の収穫で足したものを含む）、サイクルのマイルストーンの節、振り返りの「計画から実装への逆向きの照合」、台帳である。依頼には読む版を `be5b3c7` と書き、作業ツリーを読まないよう求めた（`guides/dev-cycle.md`「依頼の型」）。Codex は `git show` で、Claude は `git archive` で取り出したファイルを読んだ。どちらもテストは流さず、ファイルと行を照らした。Claude のサブエージェントは最終報告を返さずに終わり、依頼に書かせた控えのファイルから結果を読んだ。

## 違和感

- **取り込みの今日が、単価の今日の入口を通らない**（Claude）：取り込みの反映と CSV の検証は、`Sales::ItemPrice.today` ではなく `Date.current` を直に使う。いまは同じ値なので食い違いではない。OI-117 で業務の今日の入口を 1 つ置く案を選ぶと、ここも直す範囲に入る（OI-117 の行に書いた）
- **`sales:backfill_item_prices` が規則を評価せずに単価の行を書く**（Claude）：知見の収穫で足した「GraphQL を通らない入口は同じ規則を評価する」は、データの移行のタスクを名指ししていない。移行は操作者のいない運用の工程で、改定の予約・訂正とは別の操作である。OI-118 の決め方に合わせて書く
- **公開 API のソースのキーワード引数**（Claude）：`Sources::PublicApiSource` が記録時点のキーワード引数を取り、同じ値どうしだけをまとめる。`graphql-schema.md`「ページングと N+1」はこれを書いていない。矛盾ではないので記録だけにした
- **読み取りの一覧に無いフィールド**（Claude）：`ReceivedInvoice.lines`・`ReceivedInvoiceLine.purchaseOrderLine` の公開 API が、`graphql-schema.md`「読み取りの一覧」の発注側の表に無い。記録だけにした
- **ダッシュボードの受注の件数**（Claude）：全受注を読んでから数える。改善の候補 IB-34 にある
- **所有の条件の再発防止**（Codex）：相手から読む経路の無い表では、RLS が scope の欠けを隠す。IB-35 とまとめて扱う（再発防止と改善の探索）

## 再発防止へ渡すもの

「文書が正」の裁定は D2・D3・D9 の 3 つである。D2・D3 は、M28 で残す項目の規則を許した一覧に具体化したとき、表の説明と ADR の要約の 2 か所に前の言い方が残ったもので、直す前の形を種類で数えなかった（`dev-cycle.md`「実装レビュー」）。D9 は、規則が回し方の文書にだけあり、コメントを書く人が読む `comments.md` と Cop に無かった。D1 は作者の判断だが、所有の条件が RLS に隠れて壊しても落ちないことは、振り返りの想定外（二重の守り）と同じ種類なので、そこで扱う。
