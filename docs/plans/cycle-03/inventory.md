# サイクル 03 の台帳の棚卸し

サイクル 03（M36・M25・M26・M28・M27・M29）の終わりに、残件と改善の候補の 2 つの台帳を全部読み直した記録である。手順は `guides/cycle-end.md`「5. 台帳の棚卸し」にある。作者への一覧は、サイクル末の PR の本文の冒頭に貼る。

## 作者への一覧

作者の判断が要る `blocked-user` と、作者が不在の間に取りまとめ役が決めた `judgment` である。内容と判断の理由は `plans/open-items.md` の各行にある。作者が最初に読む問いを先に置き、残りを ID の順に並べる。

### 先に決めてほしい問い

1. **業務の「今日」をどの時刻帯で決めるか（OI-117）**。受注日・発注日・出荷日・検収日・請求書の発行日・単価の有効日は、アプリの時刻帯が UTC のままなので `Date.current`（UTC）で決まり、日本時間の 0〜9 時の操作は前日の日付になる。ダッシュボードの今日だけは設計文書のとおり日本時間で決めるので、その時間帯は受注日とダッシュボードの今日が 1 日ずれる。(a) `config.time_zone` を `Asia/Tokyo` にする、(b) 業務の今日を返す入口を 1 つ置く、(c) UTC のままにしてダッシュボードも UTC に揃える、のどれかを選ぶ。シードと画面の日付が決まるので、M32 の前に要る
2. **操作者を取らない公開 API を規則で認めるか（OI-118）**。通知の宛先・ジョブの操作者・再送・取り込みの再登録・単価の移行の公開 API は、操作者を取らず、多くは所有の条件を書かずに RLS だけで自社に絞る。`graphql-schema.md`「認可」は例外なく「操作者を取る」「RLS に任せない」と書く。いまは境界を越えていない。(a) 操作者のいない入口の規則を足し、所有の条件を明示する形に直す、(b) 例外を作らず、システムの操作者を渡す形に直す、のどちらかを選ぶ（逸脱検査 D1 で 2 系統の裁定が割れた）
3. **`correctItemPrice` の理由の長さの上限（OI-120）**。ほかの理由と同じ 200 文字にするかを決める

`bin/check-open-items --due` を、サイクル 03 で終えたマイルストーン（M36・M25・M26・M27・M28・M29）のそれぞれで流し、すべて通った。引当先のマイルストーンを終えたのに残っている `open` と `blocked-user` は無い。`judgment` は作者の確認を待つ行で、`--due` は止めず、作者は上の一覧で確かめる。

閉じた行は無い。足した行は OI-117（業務の日付。IB-32・IB-41 を移した）、OI-118〜OI-121（逸脱検査 D1・D6〜D8）である。引当先を後のマイルストーンにした行は、その節の作るものに ID と作業を書いた（M30 に OI-118〜OI-121、M32 に OI-117）。
