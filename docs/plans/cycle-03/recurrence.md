# サイクル 03 の再発防止

サイクル 03（M36・M25・M26・M28・M27・M29）で直し終えた指摘と食い違いの原因をたどり、同じ種類が再び起きない仕組みを足した記録である。手順は `guides/cycle-end.md`「4. 再発防止」にある。直すこと（是正）は各マイルストーンと逸脱検査で済んでいるので、ここでは予防だけを扱う。知見の収穫（`harvest.md`）に書いた知見は、ここに書かない。

読んだものは、実装レビューの指摘（High は M25 の 1 件、Medium と、振り返りで 2 回以上と数えた種類の Low）、逸脱検査の食い違い（`conformance.md`。「文書が正」の D2・D3・D9 と、前の形が残った D4）、振り返りの想定外と回し方の改善の提案である。指摘は、振り返りの「指摘の数」の種類ごとにまとめ、まとめた行に出どころをすべて挙げた。

## 機械にした検査と、壊して落ちることの確かめ

どの検査も、先に spec を書いて落ちることを見てから、実装か表を足した。壊したファイルは複製から戻した。

| 検査 | RED | 壊し方と落ちたもの |
|---|---|---|
| `spec/db/lock_sites_spec.rb` の DB の関数 | 関数を集める形にした直後、表に行を足す前に流した。48 examples のうち「ロックを取るメソッドと DB の関数は、すべて表にあり」が、表に無い `DB:invoice_children_issued_immutable` で落ちた | `structure.sql` の関数から `FOR SHARE` を外すと、表の行がロックを取らないので落ちる。`closing_lock_spec.rb` の example の群の名前を変えて、行に書いた「公開 API を通らない明細の書き換え」が現れないようにすると、その行の確かめが落ちる |
| Cop `FactoryOps/NoHistoryComment` の台帳の ID | Cop の spec に「台帳の ID を落とす」を足して流し、9 examples, 1 failure | Cop の照合から台帳の ID を外すと、同じ example が落ちる。`spec/platform/logging_spec.rb` を `OI-35` のコメントのある版に戻すと、`bin/rubocop` が 1 件を出す |
| `spec/platform/ci_checks_spec.rb` | 一覧を直す前に流し、ワークフローの `bin/brakeman`・`bin/bundler-audit`・`bin/check-branch-coverage`・`bin/check-commit-refs`・`bin/rails` が一覧に無いと落ちた | 一覧から brakeman の行を消すと、`config/ci.rb` から brakeman の工程を消すと、それぞれ `bin/brakeman` が無いと落ちる |
| 表の行列の `RETURNING` の無い INSERT（IB-30） | テストの DB で `stocks` の `owner_write` の `WITH CHECK` を `true` にし、足す前の spec を流すと 804 examples, 0 failures で、何も落ちなかった | 同じ壊し方で、足した後の spec は `stocks` の 5 ペルソナの「相手の名義で INSERT できない」の 5 件が落ちる。ポリシーを戻すと 0 failures |

`spec/db/lock_sites_spec.rb` の DB の関数の行は、いまはトリガー 1 つで、競合テストを結んだ。DB の関数の名前は spec に現れないので、行には確かめる example の名前とエラーの文を `mentions` に書いた。
