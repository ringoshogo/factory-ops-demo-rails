# サイクル 03 の振り返り

サイクル 03（M36・M25・M26・M28・M27・M29）の計画が実装にどれだけ合っていたかと、回し方そのものが働いたかを評価した記録である。手順は `guides/cycle-end.md`「1. 振り返り」にある。ここで挙げた想定外は、知見の収穫（`harvest.md`）と再発防止（`recurrence.md`）の入力になる。

読んだものは、計画レビューの証跡（`plan-review.md`）、実装レビューの証跡（`implementation-reviews.md`）、サイクルの commit の履歴（`201290a..4122a39`）、計画レビューの後に `implementation-plan.md` を直した commit、台帳 2 本、PR #42〜#47 の本文と CI の記録である。取りまとめ役がレビュアーと実装者を動かしたときに見たこと（レビュアーの報告の届き方、実装者の待ち）は、リポジトリに残らないので、ここに書いた。

## 想定外

| 想定外 | 原因 |

## 回し方の改善の提案

`guides/dev-cycle.md` か `guides/cycle-end.md` への変更として書く。機械で止められるものは、再発防止（段階 4）で検査を足すので、ここでは提案だけを書く。

1. **レビューの結果は、待っている者に届く形で立てる**（`dev-cycle.md`「独立したレビュアー」）。レビュアーを立てた者が最終報告を受け取る形（名前を付けない Agent）にし、結果をファイルにも書かせて、届かなかったときの控えにする
2. **完了の前に流すコマンドの一覧を CI と一致させる**（`implementation-plan.md`「共通の完了条件」、再発防止で検査にする）
3. **役割の制限を決めたら、制限する値を書く入口をすべて挙げる**（`dev-cycle.md`「1. 計画レビュー」の観点 1）
4. **RED の記録の代わりに何を残すかを決める**（`dev-cycle.md`「テストから書く」）。RED は期待の不一致で落ちたものに限り、RED を見なかった spec は壊して落ちる記録で代える
5. **2 つの守りが同じ条件を持つときは、片方ずつ、もう片方を通らない経路で確かめる**（`guides/testing.md`、再発防止で検査を足す）
6. **PR の base を main にする**（`dev-cycle.md`「ブランチと PR」）。前の段のブランチを base にすると、前の段のマージで上の段の PR が閉じる
